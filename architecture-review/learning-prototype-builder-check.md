# 学习能力与交互原型：独立构建检查

日期：2026-10-15。范围：学习设计 v0.1，以及 R04 冻结的 v0.7 总体/详细设计；只检查会改变构建计划的问题，不作全架构认证。

结论：浏览器原型的实现方向已足够明确，可以继续制作，无需再问用户。下列三项需在 P3c 系统实现计划前补齐；它们不阻塞当前浮点机制演示。

1. **正式模型究竟学习并输出什么？** 学习设计 §2/§6 要求 CPU burst 预测和“保留集预测误差”，§4 又选择只调整既有评分/时间片头；v0.7 详细设计 §8.1 的四个输出只有任务分数与三个时间片分数，没有 burst 预测。应明确：新增预测头/模型版本，还是保持四输出并采用策略学习目标与对应验证指标。这里改变模型包、自检、标签和训练任务，不只是留给实现者的整数算法细节。浏览器三权重回归已明确为不同模型，不应自动当成正式四输出模型的学习方案。

2. **谁在训练器可见之前分离验证标签？** §3 给训练器“只读反馈”，流程图把含执行结果的反馈缓冲直接交给训练器；§4 又要求训练器不能读取保留验证集标签。若整体反馈环可读，冻结批次后再划分无法收回已读标签。需明确由受信任采样/分集方先分区，仅向训练器映射训练视图，验证标签留在独立权限域；或明确采用独立来源的保留集。该选择影响缓冲所有权与映射，不能仅靠训练代码自律满足现有隔离表述。

3. **热切换时，模型相关自检的预期答案如何一并更新？** v0.7 详细设计 §8.4 由内核持有预期输出；学习设计 §6 更换权重后进入 SELF_TEST，但未交代新答案的可信生成与绑定。旧权重的答案通常不适用于新权重。应规定独立验证服务按候选生成并封存模型相关向量/答案，其摘要与候选绑定，由发布事务安装，回退时恢复上版对应集合；固定算子一致性向量则可以保持不变。否则有效候选可能全部自检失败，或实现者直接信任训练器自报答案。

预算与恢复：未发现需要改变当前原型计划的具体矛盾。后台与控制预算已分账且不随状态刷新；合法限流优先于公平保护；健康故障消耗唯一重建机会、耗尽后保持确定性模式的限定，足以覆盖一般“切回上版”叙述。专项事务、抢占和恢复交错验证已明确留到 P3c。

原型声明：文稿清楚区分浏览器真实浮点参数更新、模拟时间/调度和未实现的 ARM 整数学习，没有发现虚报已经实现操作系统学习或已测得性能的表述。本检查未检查尚在制作的 HTML 成品，也不确认它已通过点击验证。

## 定向复核：三项修订

2026-10-15：重新读取修订后的学习设计，仅复核上述三项。

- **正式学习目标：已解决。** 正式模型保持四输出，冻结编码器和缩放，在输出头进行有界整数坐标搜索；验收采用独立负载模拟调度指标。burst 预测与误差门槛明确仅属于浏览器替代实验。度量归一化等后续冻结细节不再构成此次构建方向歧义。
- **验证标签隔离：已解决。** 4 MiB 总池内明确划分原始、训练、验证页池；受信任代理先分集，训练器能力仅映射训练页，不能读取原始环或验证页。保留集暴露后的复用限制也已说明。
- **候选相关自检答案：已解决。** 独立验证服务明确进入可信计算基础，使用受保护整数参考生成候选答案，独立候选运行时复核，并封存、绑定候选及票据；旧模型答案不得直接用于新权重。

结论：这三项没有剩余的重要构建歧义，可据此继续当前原型及后续 P3c 计划。本结论不扩大为全域架构审核通过，也不代表系统或 HTML 原型已完成运行验证。
