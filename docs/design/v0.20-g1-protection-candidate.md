# SnapshotProtectionStore 字节候选

本候选落实 [G1 D6](v0.20-g1-media-freeze.md#d6-保护状态载体与合并规则) 的独立保护状态载体。块号为 4268，系统 inode 为 227。采用 D1.5 的 40 字节信封和整块 CRC32C，按小端解释整数。字节精确冻结仍需设计权威审定完整 D7 交付件。

## 候选载荷

| 块内偏移 | 宽度 | 字段与约束 |
|---:|---:|---|
| 40 | 2 | 载荷版本 1 |
| 42 | 2 | 载荷长度 168 字节 |
| 44 | 4 | 保留，全零 |
| 48 | 8 | 非零保护代际 |
| 56 | 8 | 非零 live_view_epoch |
| 64 | 8 | 保守累计在线年龄，单位 ns |
| 72 | 64 | 八槽保留截止值，按槽号排列，单位为累计在线 ns |
| 136 | 1 | 写门，0 为关闭，1 为开启 |
| 137 | 1 | 恢复阶段，0 为空闲，1 为已准备，2 为已恢复且仍冻结 |
| 138 | 6 | 保留，全零 |
| 144 | 32 | 独立开门证明摘要，写门关闭时全零 |
| 176 | 32 | 待处理恢复义务摘要，恢复空闲时全零 |
| 208 | 3888 | 保留，全零 |

已准备和已恢复且仍冻结的阶段均要求写门关闭并保留非零恢复义务摘要。写门开启需要空闲阶段与非零开门证明摘要。两个摘要的持久来源和精确原文仍需随 SnapshotRequestStore 与 OPEN_WRITES 证明格式共同审定。运行时授权继续核对当前 BootEpoch、保护代际、已确认事务和独立权限。

保留截止值可能早于当前在线年龄。GC 仍须取得退出保留的独立证据，核验活动根与所保留历史根的引用。槽位复用、计数递增、未知提交及恢复合并遵循 G1 与基线事务约束。

## 独立核对

Python 编解码器和 Rust 编解码器读取同一组固定向量。向量记录展开后的 4096 字节 SHA-256，并覆盖关闭、恢复准备、恢复完成、开门、校验不符和保留字节非零。Rust 测试同时核对当前挂载入口拒绝候选载荷并接受全零载荷信封。
