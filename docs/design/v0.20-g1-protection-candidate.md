# SnapshotProtectionStore 字节格式

保护状态独立保存在块 4268，系统 inode 为 227。采用 D1.5 的 40 字节信封和整块 CRC32C，整数按小端解释。 [G1 D6](v0.20-g1-media-freeze.md#d6-保护状态载体与合并规则)

## 载荷

| 块内偏移 | 宽度 | 字段与约束 |
|---:|---:|---|
| 40 | 2 | 载荷版本 1 |
| 42 | 2 | 载荷长度 168 字节 |
| 44 | 4 | 保留，全零 |
| 48 | 8 | 非零保护代际 |
| 56 | 8 | 非零 live_view_epoch |
| 64 | 8 | 保守累计在线年龄，单位 ns |
| 72 | 64 | 八槽保留截止值，按槽号排列，单位为累计在线 ns |
| 136 | 1 | 写门，0 为关闭，1 为开启 |
| 137 | 1 | 恢复阶段，0 为空闲，1 为已准备，2 为已恢复且仍冻结 |
| 138 | 1 | 清理冻结，0 为允许根移除，1 为禁止新根移除 |
| 139 | 5 | 保留，全零 |
| 144 | 32 | 独立开门证明摘要，写门关闭时全零 |
| 176 | 32 | 待处理恢复义务摘要，恢复空闲时全零 |
| 208 | 3888 | 保留，全零 |

已准备阶段的恢复义务摘要取同视图 PENDING 或 UNKNOWN RESTORE 的 `request_digest`。已恢复且仍冻结阶段绑定已完成 RESTORE 的 `result_digest` 及新视图代际。两阶段都保持写门关闭。OPEN_WRITES 同事务推进保护代际，记录 `DONE` 回执，并将回执的 `result_digest` 写入开门证明摘要。读取时核对更早完成的同视图 RESTORE 回执，用原恢复请求键和前一保护代际复算 OPEN_WRITES 的请求摘要。被当前保护状态引用的记录必须保留。

冷挂载确认上述介质证据后仍保持运行时写门关闭。开门另核对当前 BootEpoch、恢复门及独立保护权限，短期和长期两层都须有已验证的 ACTIVE 根。保有历史根且缺少原生 CoW 时，普通写入保持关闭。 [快照请求对象与端点](v0.20-g1-snapshot-wire.md)

`FREEZE_SET` 置清理冻结并关闭写门。`FREEZE_CLEAR` 只清除清理冻结。`OPEN_WRITES` 保留清理冻结值。已进入 `DELETING` 的快照仍须按原根移除事务和当前位图完成对账，取得持久检查点后才能交回可分配空间。宿主事务覆盖恢复后开门和 GC 退休。原生快照变更服务、`FREEZE_CLEAR` 维护持续开门证明的执行链仍待接线。

保留截止值可能早于当前在线年龄。GC 仍须取得退出保留的独立证据，核验活动根与所保留历史根的引用。槽位复用、计数递增、未知提交及恢复合并遵循 G1 与基线事务约束。

## 独立核对

Python 和 Rust 对照同一组固定向量。向量记录展开后的 4096 字节 SHA-256，覆盖关闭、恢复准备、恢复完成、开门、独立清理冻结、校验不符和保留字节非零。旧兼容挂载仍使用全零载荷信封，生产统一卷在签名布局下检查非空载荷与相关持久记录。
