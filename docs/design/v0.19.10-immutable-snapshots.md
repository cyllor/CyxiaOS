# CyxiaOS V0.19.10 不可变快照与防勒索设计候选

**状态：DRAFT / G1 NOT_READY。** 本增补是对正式 V0.19.9 设计的候选范围变更，面向 CyxiaOS-V0.20 软件分支；不是一个已经存在的正式 V0.19.10 DOCX 的复制。以 [V0.19.9 基线](baselines/v0.19.9-implementation-spec.txt)、[V0.20 目标架构](v0.20-native-local-system.md) 和 [V0.18 快照历史实现](../implementation/v18-immutable-journal-snapshots.md) 为依据。除不可变快照范围、相应资源和验收要求外，保持基线安全边界；本次不修改代码。

## 1. 范围与安全目标

将业务文件系统不可变快照列为单机原型的强制设计能力，归属 D04 与 D12 协同，不新增 D16 或 AI 动作族。持久日志负责崩溃一致性，快照负责保留合法覆盖、删除或恶意批量修改之前的数据版本，两者互不替代。保护对象为本机业务文件、目录树、捕获边界与受保护的快照目录和保留状态。

覆盖普通业务进程（包括持有正常 WRITE/UNLINK 权限的恶意进程）试图覆盖或删除历史文件、越权操作快照、绕过保留期、耗尽空间以及崩溃、I/O 结果未知和恢复重试。信任 EL1、受保护文件服务和恢复机制；不承诺抵抗恶意宿主、能任意改写物理介质的攻击者或整盘回滚。摘要/CRC 提供完整性检测，不等于针对任意物理篡改的可信根；不可变快照也不替代离线备份。

## 2. 权威对象与不变量

| 对象 | 强制约束 |
|---|---|
| 当前业务视图 | 每次持久发布有唯一受保护 live_view_epoch 与事务边界。 |
| 快照身份 | FS UUID、单调 snapshot_id、槽及槽代际共同标识；公开 ID 不授予能力。 |
| 历史根 | 捕获已确认提交视图；所有可达数据/目录/extent 元数据只读，不能原位覆盖。 |
| 保留状态 | 持久、单调、只能延长；快照恢复不得回退截止点、保护代际、请求水位。 |
| 快照请求 | 按真实主体和代际去重；同键同摘要返回原状态，同键异摘要拒绝；UNKNOWN 不重做。 |
| 恢复控制 | 独立保护门、恢复授权、目标身份、新旧视图代际和提交证明；模型不持有这些权限。 |

COW 的新分配、块所有权、引用、位图和提交边界必须同一确定性账本核验。历史可达块不得被活动视图或 GC 释放。所有副作用受原有能力、配额、事务和真实完成协议约束；无可靠证据保持冻结、只读或 UNKNOWN，禁止伪造成功。

## 3. 创建、历史读取和保留

1. 创建前核验真实快照创建权限、请求键、槽/空间/日志/完成额度，登记持久请求。
2. 关闭新的相关业务写准入，完成此前已受理、需纳入捕获边界的脏数据；冻结权威提交边界，不捕获未证实的部分事务。
3. 生成独立只读历史根、完整性摘要、身份和保留截止；按 redo/FLUSH 顺序发布快照及终态记录。失败或掉电后以真实事务证据恢复，不重新选择捕获时刻。
4. 历史读取必须通过明确授权的 FS UUID 和路径前缀解析自己的历史目录树，不回退到活动视图；历史句柄只读，并在关闭前钉住其快照根。普通 FileCap 及业务所有权不自动取得快照控制权。
5. 保护期内不允许删除、覆盖、缩短保留或因压力提前回收。延长保留走授权确定性事务。到期后仍需核验真实引用、GC 条件与周期保护下限。

### 原有实现参数作为待核定候选

历史 V0.18 已定义 8 槽（6 周期、2 按需），短期 3 槽每 6 小时、保留 18 小时；长期 3 槽每 48 小时、保留 144 小时；按需 1 小时最少、24 小时默认、7 天最多。候选沿用这些值以复用既有实现，G1 须与新版磁盘布局、资源账本和测试窗口共同锁定。固定容量不互借；周期层至少保留一个可验证保护点。保留期使用受保护、持久、单调在线年龄（历史实现为 60 秒粒度）；关机、宿主时间跳变或 AI 输出不得提前推进。真实保留期与注入测试时间分别标记。

## 4. 安全大脑的辅助链路

沿用 V0.19.9 SecurityFinding v2。安全大脑可基于授权的脱敏计数、文件修改/删除频度、异常失败及快照容量压力提出 OBSERVE 或 REVIEW_RESTRICTION。目标与类型由受保护评估上下文登记，模型不制造身份、路径授权、处置条件或特权票据。

监督者核验来源、代际、快照时效和去重，确定性控制器依据真实观测和冻结规则独立复核。允许的预授权收紧包括停止新风险写准入、保护性冻结及请求创建保护点；保护创建仍须满足空间与日志硬门。安全大脑不得直接修改文件、释放/删除快照、缩短保护期、恢复卷、开门或生成执行回执。规则本身、必要恢复以及周期保护在 AI_DISABLED 下独立推进，SHADOW 仅记录。模型不确定、建议过期或队列满时按确定性规则回退。

## 5. 可信恢复与 GC

恢复需显式快照身份、真实恢复能力和预授权规则。先冻结写入并登记持久恢复准备状态，明确此前已受理写的处理方式（保留并结算或经证明丢弃易失内容）；核验整个目标历史根与资源，按事务发布新业务视图与新的 live_view_epoch。旧 LIVE 句柄、能力和缓存不能访问恢复后的新对象，历史句柄仍绑定原视图。恢复不回退 BootEpoch、保护代际、允许的安全规则/密钥代际、授权撤销、快照身份和保留水位；ACL、inode 代际和持久收据的合并必须由 G1 统一介质契约定义，无法证明授权一致时拒绝恢复。禁止恢复普通业务数据导致旧授权复活。

恢复成功后保持写门关闭，只有具有真实恢复完成证明、当前保护代际及独立权限的确定性开门路径可以重新开放。不依赖模型或自动重启开门。持久请求结果确认不解除仍存在的保护门。

GC 先关闭新的相关根移除，验证所有活动/历史根及系统对象的块可达性；带引用、仍有 DMA/事务义务或未知状态的块不得释放。删除先进入 DELETING，只有位图事务、检查点、设备静默、缓存/引用收尾全部证明后才成为 FREE 并允许新分配。容量不足拒绝新工作，不驱逐仍受保护的历史版本；不可证明的最新超级块/日志代际进入 RECOVERY_REQUIRED/EIO。

## 6. 接口与唯一事实来源（G1 阻断项）

不增加 V0.19.9 的 19 个系统调用号。快照协议使用既有 0x50 本地服务调用的独立受保护端点，沿用原有语义分类：CREATE、EXTEND、DELETE_EXPIRED、RESTORE、LIST、QUERY、HISTORY_OPEN、FREEZE_SET、FREEZE_CLEAR、OPEN_WRITES、QUERY_REQUEST、ACK_REQUEST。历史 FileServiceSchemaV2/SVC 0x45 仅作为既有代码和迁移参考，不能直接充当新版 Syscall ABI、FileServiceRequest v4 或 Reply v3。G1 冻结真实主体/端点/能力位、字段和枚举、请求/应答、权限原子门、恢复代际及黄金反例；普通读写权限不能隐含快照管理权。

历史 V0.18 卷使用超级块 v2、FSControl、SnapshotCatalog、8 个槽及业务 COW 数据区，另有旧集群固定对象；V0.19.9 规范则保留超级块 v1、data_start=4118 及 BootEpochStore/Receipt/ACL/SecurityState 固定系统对象。二者**不是同一可写格式**。目标保持 512 MiB、4 KiB 块和单机原生范围；G1 必须确定统一的新版本化介质布局、系统对象位置、业务 inode/extent 边界、根/ACL/收据与位图事务闭包，去除旧集群依赖而不删除历史保护义务。不能只改版本号、混读两套固定偏移或静默重新格式化旧卷。兼容路径须明确离线导出导入或验证过的迁移，无法证明保留期/快照/保护状态连续时禁止可写迁移。

现有历史实现的 68 KiB 管理预算、128 KiB CoW 版本预算和复用事务工作区的 48 KiB GC 工作区只作为 G1 核算输入。确认它们是否能在 V0.19.9 的 8 MiB 控制池、8 MiB 进度池、10 MiB FrameMeta 和业务总账中独立计账；不能隐藏新常驻池或消耗最后完成/恢复额度。参数注册表必须为槽数、周期、保护时限、空间下限、引用容量、恢复和 GC 截止提供唯一来源和测试映射。

## 7. 强制验收补充

保留原 127 个稳定 ID 与证据纪律，下表是新增断言追溯，不声称新的独立测试 ID 已冻结。

| 断言组 | 必须观察到的结果 | 关联原用例/专项 |
|---|---|---|
| COW 历史数据 | 创建保护点，改写/删除活动文件后历史字节不变；目录、inode 复用也不破坏历史根。 | SEC-F、A10 |
| 权限、保留 | 普通 WRITE/UNLINK/文件所有者不能删除受保护快照或提前过期，AI 无管理权限；时钟/重启不绕过保留。 | SEC-F、SEC-S、J13 |
| 断电与重试 | 在创建、恢复、删除、GC 的提交和 FLUSH 边界注入故障；已确认版本可查，未知状态不重做。 | SEC-F10–F12、J03、J05 |
| 恢复与隔离 | 新视图 epoch 单调，旧 LIVE 句柄/能力失效，历史视图仍只读；安全状态不回退，未授权不得开门。 | SEC-P、SEC-F、SEC-M、SEC-S |
| 空间与进度 | 普通池耗尽和快照槽满时保持保护下限与恢复额度；未知引用不复用；报告实际退化。 | A11、J04、SEC-F |
| 双脑负向 | 伪造/过期/洪泛 Finding、AI_DISABLED 和 SHADOW 下，禁止模型越权、自动解除保护或热路径等待模型。 | A03、H01–H05、J13 |
| 端到端 | 原生 QEMU 执行真实创建→改写→历史读取→可信恢复→独立开门；验证客体回执和停止后的介质，不只检查宿主模拟。 | G2/G3/G4-QEMU |

必须分别记录独立静态/模型/原生运行及实体架构证据。历史 V0.18 验证记录的宿主测试与原生构建通过不代表当前分支通过；其原生端到端历史结果为 FAIL（预算超限），不能重新标为 PASS。本次仅同步设计，所有新断言均 NOT_RUN，G1 NOT_READY。待统一格式/ABI 与工程证据交付后才能申请冻结与验收。
