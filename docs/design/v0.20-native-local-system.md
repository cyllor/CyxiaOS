# CyxiaOS V0.20 原生单机架构设计增补（规范草案，尚未验收）

设计状态：**DRAFT / IMPLEMENTATION INCOMPLETE**，绑定分支 `work/v020-native-control-safety`，适配软件版本 `0.20.0-dev`。本文覆盖旧《CyxiaOS 最小化原型设计文档》关于 D16 双节点集群与动态控制核的过时条款；不得反向读取旧文档而重新启用这些机制。*本文是目标契约，而非实现已满足的声明。*

## 1. 可信边界与固定核心

针对 4-vCPU ARM 参考机型，受保护角色固定为：**CPU0：确定性 EL1 机制/设备 broker；CPU1：唯一 AI 控制核；CPU2/CPU3：业务核**。同一个逻辑单控制核的预算不得因运行运营、安全、训练、Shadow 或 Canary 工作而复制。CPU0 不运行第二个 AI 控制器；CPU2/3 不准冒用控制预算。控制 CPU 失效：禁止新 AI 计划与资源优化、停止并保留在途，进入 SAFE_EXEC，不将 CPU2 或 CPU3 自动升级为 C。

x86-64 必须冻结自身经验证的独立物理/逻辑核心映射，不能以本段的 ARM CPU 编号代替真实 x86 拓扑证明。若可用核心不足以建立受保护机制、专用控制及业务隔离，拒绝相应多核配置，不将多个逻辑角色静默同核复用。

EL1 的控制能力是资源/能力/策略账本与独立执行器的权威；模型服务只能提交 **Advice** 数据。硬约束、身份、授权、候选合法性、计划版本、对象代际、CPU 归属、持久化事务与设备完成由原生确定性机制独立核验。

## 2. 运营 AI 与安全 AI 双大脑

两大脑必须分别建立原生 EL0 任务身份/代际、独立页表与专有不可写共享映射、独立模型状态、独立有界 IPC 建议队列及分别受控的 CPU 时间/内存配额。禁止共享可写模型权重或任一模型对另一模型的消息缓冲区写入。运行时必须在**同一个 CPU1 全局控制预算**中扣费；不能各自领取 70 ms/100 ms。

安全大脑不得拥有最终安全拒绝豁免、资源授予、页表更改、设备路由、文件提交或策略发布的权限。它提交风险分析/建议；运营大脑提交性能/服务建议。可信确定性审查器从当前内核快照构造 Scope，拒绝跨身份/跨目标/过期/旧代际/非法候选。建议冲突采用合法、可追责的确定性基线，不让两个 AI 互相投票产生新的授权。

**现状：** 仓库已有 `control_plane::fixed::Pair` 独立逻辑建议槽、`advisory::Controller` 和 `Manager::review_brains`；两个完整独立 EL0 推理进程、原生页表隔离及运行时费用证明仍未完成，不可将“邮箱隔离”表述为“进程隔离已验证”。

## 3. 统一控制预算/真实计费

参考计量窗口采用客体单调时间对齐的 **100 ms**，固定控制核的总控制工作至多 **70 ms/100 ms**，保留必要进度及上层恢复额度；旧最小原型给出正常必需 61 ms/100 ms，最多额外 9 ms 供训练、验证、Shadow/Canary 共用。所有工作必须先从**同一 CPU1 物理预算账本**预约，返回唯一 `ControlCredit` 并验证 CPU1、所属窗口、代际、资源归属和序列；不得跨窗口、控制器重启或模型切换重置已花费额。

每次完整收费包含：模型输入准备/编码、受限推理、独立校验、发布、返回路径、训练/验证、观测/反馈、服务中断的可归属部分。超出 reservation 的实际用时必须记录、隔离并停止新优化。墙钟延迟与真实执行 CPU 时间单独记录，宿主 QEMU 停顿不能既当成处理成本又忽略真实费用；不可用仅增加 wall headroom 伪称“已解决预算超限”。

最小判定记录：`source_sha`、`guest_image_sha256`、`model/schema hashes`、`controller_epoch`、`cpu_id`、`window_id`、`reserved_ns`、`actual_ns`、`control_total_ns`、`physical_total_ns`、拒绝与隔离原因及 QEMU 版本/命令。低优先级工作在必需任务尚未兑现时不可消耗后者的保留时间；模型停机不阻断业务热路径。

## 4. 全本地域平权 AI 接入

保留十五个原生本地一级域 D01–D15，其架构地位和接入责任完全平等：D01 调度、D02 进程、D03 内存、D04 文件、D05 IPC、D06 中断、D07 定时器、D08 系统调用、D09 I/O、D10 网络、D11 设备、D12 安全与隔离、D13 背景能耗代理、D14 诊断与恢复、D15 HAL/串口。CPU、虚拟内存、日志文件系统不再被赋予首要/首批强化级别；文件日志是文件系统的一部分。

统一执行闭环：受保护采样 `Snapshot` → 本地模型 `Advice` → 候选和权限/资源/代际确定性审查 → 唯一计划/受保护执行器真实 `APPLIED` → 行为、成本、失效和反馈。仅有模型 hash、字段变化、候选分数、待提交计划不构成生效证明。每域至少两组能产生不同合法动作且真实行为差异的可复现实验；错版/超限/非法权限要走明确 SAFE_EXEC，不允许旁路。

## 5. 六个安全方向原生集成边界

| 方向 | 必须绑定的权威原生执行点 | 原生必测故障 |
| --- | --- | --- |
| SEC-P 进程 | `task_spawn/exit`、可信任务注册表/CPU 布局、引用/终态 | 旧代际、非法包、CPU0/CPU1 任务投递、退出与新建竞态 |
| SEC-F 文件 | EL0 文件服务 ABI、能力/代际、redo/COMMIT/FLUSH 原子事务 | 重复路径、系统对象越权、FLUSH/断电各边界与 UNKNOWN |
| SEC-M 内存 | 用户映射/页表 owner、W^X/清零、TLBI ACK、DMA pin | 非法别名/owner、跨核 ACK 缺失与页重用 |
| SEC-N 网络 | 原生 TCP endpoint/会话代际、TLS1.3 验证、只读 Echo adapter | 伪造来源、错误 ALPN、握手拥塞、断链及 TX/DMA 未完成 |
| SEC-D 设备 | VirtIO 完成 token/描述符代际、可靠复位、IRQ 路由 | 超时/重复 ACK、部分完成、设备故障、未知 DMA 引用 |
| SEC-S 系统调用 | 入口稳定复制、现存 ABI 白名单、受保护发布者 | 修改用户缓冲、伪造模型角色、非法批量项、重复副作用 |

SEC-N 的 `RateLimiter` 与 `net-transport::Admission` 不得对同一连接同时成为授权账本；选择一个唯一权威入口后再真实绑定证书、端点来源、TLS drain、VirtIO net completion。SEC-F 成功持久化回复不能早于事务与 FLUSH 证据；SEC-D/TLB/DMA 的 UNKNOWN 不得由模型或超时释放。

保留原 G0–G4 验收门：G2 六安全方向原生执行、G3 十二项跨域交错、G4 全系统安全验收；并分别在 `AI_DISABLED`、`SHADOW`、`ASSISTED` 下收集可信结果。原有 48 SEC 单域和 12 J 主机模型函数只能算组件证据。**在完整 QEMU/目标原生记录出现之前，G2–G4 为 NOT_RUN。**

## 6. 不再拥有分布式功能

必须删除可达运行与构建图中的：双节点发现与成员关系、ClusterID 伙伴状态、跨节点 QUOTE/PREPARE/COMMIT/ACTIVATE、D16 远程放置、远程资源合同、跨节点 ACK_RESULT 结果保管、双节点一致性日志、自动选主与分布式恢复。清理必须同时覆盖运行时导入、Cargo features、构建脚本、Schema、测试参数、示例/文档，并核验目录和持久存储不引用旧集群保留 inode。

必须保留不依赖集群的**本机原生网络、TCP/TLS、设备接口、IPC、页缓存、redo/恢复**。移除历史持久结构需要明确迁移/拒绝旧盘版本策略，不能直接删除保留字段导致磁盘误解析。不能将原生 CyxiaOS 节点替换为运行在 Linux/Windows/Android/iOS 宿主之上的平台代理。

**当前阻塞：** `kernel/src/runtime/cluster/`、`crates/kernel-core/src/cluster/`、`crates/prototype/src/cluster/`、`crates/cluster-transport`、`crates/peer-billing` 等仍在源码/历史特性图中；尚未完成彻底移除，必须按实际构建可达性审计再改。
