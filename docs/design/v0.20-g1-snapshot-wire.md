# G1 D7 快照端点与请求对象字节格式

沿用策略 A 的 v1 超级块、固定系统对象地图及 0x50 寄存器绑定。本件定义快照端点和 SnapshotRequestStore 的字节，所有整数为小端。目录、槽、保护状态和普通文件收据沿用各自编解码器。介质校验由同一只读提交视图提供，真实调用者、当前授权、已提交效果和设备完成证据由受保护所有者取得。 [G1 策略 A](v0.20-g1-media-freeze.md)

## 快照端点请求

使用 FileServiceRequest v4 的 32B 头。魔数是 `0x43594651`，ABI 为 4，标志位和 auth_context_id 为零。payload_len 等于头后精确字节数，总长最多 1024B。request_id 非零。端点标识经 EL1 核验。x3 在 0x20–0x29 为非零选择器，在 0x2A–0x2B 等于零。输入输出范围从同一次陷入捕获，检查数值溢出、长度和重叠后复制。

FileReqKey 36B 由 16B UUID、u32 主体槽、u64 主体代际及 u64 请求序号组成。主体槽 0–13 属于普通主体，14 属于内部维护，15 属于恢复主体。SnapshotKey 40B 由 16B UUID、u64 快照 ID、u32 槽、u32 零及 u64 槽代际组成。UUID、请求序号、快照 ID 和对应的代际非零。两个键包含的槽号均从零起算。

持久操作在操作体之前放 FileReqKey，序号与头内 request_id 一致。CREATE、RESTORE、OPEN_WRITES 在请求键之后紧接 u64 当前 live_view_epoch。其余操作省略该字段。QUERY_REQUEST 和 ACK_REQUEST 在操作体内携带目标键，头内 request_id 等于查询或确认的目标序号。

| op | 操作体 | Reply v3 成功输出 |
|---|---|---|
| 0x20 CREATE | 保留时长 u64 ns、槽类别 u32、数量 u32=1 | 快照键、捕获视图代际、捕获 LSN、创建在线年龄、保留截止，共 72B |
| 0x21 EXTEND | 快照键、保留时长 u64 ns | 快照键、旧截止、新截止、当前在线年龄，共 64B |
| 0x22 DELETE_EXPIRED | 快照键 | 快照键、根撤除提交 LSN u64、阶段 u32=1、零 u32，共 56B |
| 0x23 RESTORE | 快照键、模式 u32、零 u32 | 快照键、旧和新视图代际、32B 提交事务键、关闭写门 u32=1、零 u32，共 96B |
| 0x24 LIST | 空 | 48B 状态和最多八项 128B 摘要 |
| 0x25 QUERY | 快照键 | 48B 状态和该键的 128B 摘要 |
| 0x26 HISTORY_OPEN | 快照键、路径字节数 u16、6B 零、完整路径 | u64 非零不透明历史句柄 |
| 0x27 FREEZE_SET | 当前保护代际 u64、原因 u32、零 u32 | 新保护代际 u64、清理冻结 u32=1、关闭写门 u32=1，共 16B |
| 0x28 FREEZE_CLEAR | 当前保护代际 u64 | 新保护代际 u64、清理冻结 u32=0、写门 u32，共 16B |
| 0x29 OPEN_WRITES | 当前保护代际 u64、需查证的恢复请求键、零 u32 | 新保护代际 u64、清理冻结 u32、写门 u32=0，共 16B |
| 0x2A QUERY_REQUEST | 目标 FileReqKey | 原 512B 请求记录 |
| 0x2B ACK_REQUEST | 目标 FileReqKey、32B 终态摘要 | 空 |

CREATE 槽类别 1 为周期维护，2 为按需。RESTORE 模式 1 保留已接受脏写，2 丢弃易失写。保留和在线年龄统一用 ns。请求键及所引用快照或恢复键必须属于同卷。HISTORY_OPEN 路径为规范绝对 UTF-8 路径，最长 512B，每组件不超过 63B，权限按组件边界匹配。前缀摘要为 SHA-256，即 ASCII `CyxiaOS:history-prefix:v1\0`、LE64 路径前缀字节数和前缀字节拼接后取哈希。

EL1 以真实 holder、holder 代际、启动代际、服务代际、独立端点和选择器匹配授权表。快照授权字使用 G1 D2 的 bit0–6。普通主体持有对应快照权限时可申请按需槽，内部维护角色可申请周期槽。QUERY_REQUEST 与 ACK_REQUEST 按原持久主体或已准入恢复监督者授权。先处理同键同摘要的重试，再核对新请求的视图和保护代际。

## 签名部署授权

统一卷启动清单可附 `snapshot-authority.bin` 和分离签名 `snapshot-authority.sig`。清单以小端编码。

| 偏移 | 字段 |
|---|---|
| 0 | 8 B `CYXSNA01` |
| 8 | 16 B 卷 UUID |
| 24 | u64 持久主体 ID |
| 32 | u64 持久主体代际 |
| 40 | u16 恢复请求槽 15 |
| 42 | u16 RESTORE 持有者 role1（受保护 EL1 恢复所有者） |
| 44 | u16 PROTECTION 持有者 role11（约束在已签名的原生 Supervisor） |
| 46 | u16 保留值 0 |
| 48 | u32 `RESTORE` 权限字 `0x08` |
| 52 | u32 `PROTECTION` 权限字 `0x40` |

引导信任根以 Ed25519 签名 ASCII `CYX/STARTUP-SNAPSHOT-AUTHORITY/v1`、完整 `lifecycle-packages-to-sign.bin` 的 SHA-256、完整 `file-volume.bin` 的 SHA-256 和上述 56 B。启动分别核验生命周期与卷清单。两个活体主体共用签名配置的恢复请求槽 15 和原有持久序列空间，各自只能使用授权的快照操作。 [签名输入封装](../../tools/package_v020_snapshot_authority.py) · [引导校验](../../crates/kernel-core/src/security/startup_catalog_v0199/snapshot_authority.rs)

启用该清单后，适配的 role11 签名程序从启动参数的第二个 u64 取得 `BootEpoch × 65536 + 0x5301` 端点，按第三个 u64 所载当前角色代际取 `generation × 65536 + 0x5302` 选择子。EL1 在返回陷入的已注册地址空间内配对这两个值，并核对当前文件服务代际与槽 15。内部 RESTORE 另须匹配当前受保护挂载和启动状态。真正持有卷的事务执行者须完成持久准入和提交。该所有者接线前，合格的 PROTECTION 请求返回 `EAGAIN`，保留回复缓冲、请求水位和快照页面。 [原生端点](../../kernel/src/arch/aarch64/production/signed_resident/snapshots.rs) · [四核验证器](../../tools/verify_v020_snapshot_authority.py)

## Reply v3

保持基线 128B 头，快照应答最多 2048B。completed_prefix、new_cap_selector、write_seq 和 flags 为零。持久回执的 receipt_ref 等于头内 request_id。状态从持久记录投影为 PENDING→2 BOUND、DONE→3 DONE、FAILED→6 CANCELLED、INCOMPLETE→4 PARTIAL、UNKNOWN→5 UNKNOWN。非终态返回负错误和零提交 LSN、事务键及摘要。终态携带已确认提交 LSN、事务键和终态摘要。易失成功及准入前拒绝使用 state=0。状态 0 的负错误没有输出。普通持久操作仅 DONE 附成功输出。CREATE、RESTORE、OPEN_WRITES 的 DONE 以 target_generation 返回确认的 live_view_epoch。其他持久操作的 target_generation 为零。保护变更操作返回的保护代际是请求内代际加一。QUERY_REQUEST 附随其查询到的规范记录，记录与回复头的状态、结果、事务及摘要必须一致。

LIST/QUERY 的状态字段偏移为 0 条目数 u32、4 清理冻结 u32、8 在线年龄 u64、16 live_view_epoch u64、24 保护代际 u64、32 写门 u32、36 恢复阶段 u32、40 八个零字节。写门 0 为开，1 为关。恢复阶段 0 为 Idle、1 为 Prepared、2 为 RestoredFrozen。

每个 128B 摘要按槽升序。偏移 0 为快照键，40 类别 u32，44 状态 u32，48 捕获视图代际 u64，56 捕获 LSN u64，64 创建在线年龄 u64，72 保留截止 u64，80 保留代际 u64，88 根撤除提交 LSN u64，96 元数据验证结果 u32=1，100 当前根引用数 u32，104 起全零。状态 1 为 ACTIVE，根撤除 LSN 为零。状态 2 为 DELETING，根撤除 LSN 晚于捕获 LSN。

## SnapshotRequestStore

16 页固定从 4252 起。页 0 的 40B D1.5 信封主体 UUID 及对象代际与受保护挂载上下文一致。40..56 依次为八个 u16，值为版本 1、单水位长度 128、单记录长度 512、记录总数 64、主体数 16、普通容量 48、维护容量 8、恢复容量 8。56..512 和 2560..4096 为零。旧空对象用完整合法信封加 40..4096 全零表示，同时要求随后十五页全零。

从偏移 512 顺序放 16 个 128B 水位。偏移 0 为魔数 `0x4359574d` u32，4 版本 u16=1，6 长度 u16=128，8 物理主体槽 u32，12 零 u32，16 主体代际 u64，24 已接受请求序号上界 u64，32..124 零，124 CRC32C。未登记主体的代际与序号均为零。页 1–8 每页八条记录，页 9–15 为零。记录槽全零表示 FREE。普通、维护、恢复分区依序各占六、一、一页。查询在旧序号缺记录时返回失效，ACK 退休记录时保留水位。

| 记录内偏移 | 长度 | 字段 |
|---|---:|---|
| 0 | 8 | 魔数 u32=`0x43594652`、版本 u16=1、长度 u16=512 |
| 8 | 8 | 状态 u32、操作 u16、零 u16 |
| 16 | 36 | FileReqKey |
| 52 | 36 | 32B 请求摘要、4B 零 |
| 88 | 40 | 快照键，未选定时为零 |
| 128 | 16 | 原视图代际 u64、新视图代际 u64 |
| 144 | 32 | 事务键 UUID、u64 log_epoch、u64 txid |
| 176 | 8 | 结果 i32、恢复模式 u32 |
| 184 | 32 | 终态摘要 |
| 216 | 4 | 有效内容长度 u32 |
| 220 | 128 | PENDING 或 UNKNOWN 的原操作体，DONE 的成功输出，其余全零。有效内容后补零 |
| 348 | 8 | 提交 LSN u64 |
| 356 | 152 | 零 |
| 508 | 4 | CRC32C |

PENDING=1、DONE=2、FAILED=3、INCOMPLETE=4、UNKNOWN=5。CRC32C 使用反射 Castagnoli，多项式 `0x82f63b78`，初值和最终异或均为全 1。计算各自完整页、记录或水位时将本级 CRC 字段置零。请求摘要为下列字节依序拼接后的 SHA-256。

```text
ASCII CYXIA-SNAP-REQ-V1
LE16(4)
LE16(op)
FileReqKey[36]
LE64(expected_live_view_epoch_or_0)
LE32(operation_body_len)
operation_body
```

终态摘要为完整 512B 记录的 SHA-256，计算时将终态摘要和 CRC 字段置零，计算 CRC 前填写终态摘要。记录内的提交 LSN 不超过独立重放确认的介质提交边界。首头、物理分区和水位一起限定每条记录的卷身份、持久主体和请求序号。全区须检查重复键。

## 发布、恢复和确认

1. 当前主体严格接续序号，新增 PENDING 与更新水位在同一 redo 事务提交。同键同摘要重投返回原状态，同键异摘要拒绝。
2. 确定完成或确定失败后，以同一事务发布实际效果及终态。提交不明的请求保留原键与原请求体，进入 UNKNOWN。已经绑定尝试事务的 UNKNOWN 经效果核验后只能以同一事务键进入 DONE。
3. RESTORE 用原键完成且仅发布一次新 live_view_epoch，写门保持关闭。提交事实来自恢复所有者核验的原 redo、当前业务视图和实际运行状态。OPEN_WRITES 的恢复键索引原请求，实际开门由独立权限按当前视图、保护代际和确认效果验证，再持久发布开门证明。
4. ACK 需原请求身份及匹配的终态摘要。PENDING、UNKNOWN 和仍被当前保护状态引用的完成证明保留。ACK 与删除数据无关，GC 独立依据已提交根撤除、引用、保留约束及当前位图授权执行。提交不明时保留原记录或数据块。

ProtectionStore 偏移 138 持久保存独立的清理冻结位。GC 冻结阻止新根移除，已进入 DELETING 的义务可在确认全根可达性与原删除记录后继续。GC 退休将目录 FREE、保留期限清除及精确位图更新提交到同一事务，完成 FLUSH、检查点及原始回读后才交给分配器。 [保护状态持久布局](v0.20-g1-protection-candidate.md)
