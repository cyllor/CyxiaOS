## 规模为何膨胀，以及目前不能得出的结论

`tasks()` 对全部216个一级点逐一展开 before/after-ack × drop/reverse-half，形成864个分支；再对每个分支的实际恢复点展开同样四种形状及cut/final两次运行。当前campaign的新child公式为 `1 + 2P + 8ΣR_i`，其中 `P=4O`；若把两个父场景也计入，总数为 `3 + 2P + 8ΣR_i`。

旧582339次估算使用 `O=216`、每个分支均有84个恢复点的假设。本次实测的一个分支有116点。精确总量仍未知；同样不能将所有分支替换成116来宣称得到真实总量。

分类证明了不同阶段被乘入同一个二维故障图，但未证明任何两点或两分支等价。不得直接从216点缩为50点、从116点缩为66点，也不得把相同阶段名称当作可复用收据。标记事务与BootEpoch均有真实协议/持久化义务。
