# Smithay 原生交互移动与缩放

更新日期：2026-10-22。本文描述本轮实现与验收契约；最终运行结果在文末单独记录。

## 实现范围

在 CyxiaOS 自研 ARM64 内核上，两个独立的真实 libwayland 客户端通过固定 Smithay 的 `xdg_toplevel.move` / `resize` 请求启动交互。位置更新、指针抓取、缩放配置及缓冲提交均发生在客体；Mesa softpipe/GLES 合成结果经原生显示接口和 VirtIO GPU fence 呈现。

本阶段验证鼠标移动和右下角缩放。它仍是有界集成验证程序，尚未运行 `cosmic-comp`，不包含通用应用接入、窗口装饰、其他缩放边缘、触摸交互、工作区或完整 COSMIC 会话。Escape 取消没有列入本阶段客体验收；交互状态清理的单元测试不能替代该项客体证据。

实现分层：

- `ports/cosmic/smithay-multi/scene.rs` 提供窗口堆叠、命中测试和几何更新。更新位置/尺寸不改变顺序与焦点；无效尺寸或未知窗口返回错误并保留原状态。
- `ports/cosmic/smithay-interactive/interaction.rs` 提供与 Wayland/渲染器解耦的授权、抓取状态、相对起点的几何计算、尺寸约束和按所有者取消操作。
- `ports/cosmic/smithay-interactive/main.rs` 将该机制接入真实 Smithay seat、指针抓取、配置确认、缓冲提交及原生呈现。
- `user/ported/smithay_interactive_client.c` 负责独立客户端协议行为，验证实际配置与输入，创建并填写真实共享缓冲。

## 授权与状态一致性

一次交互必须绑定实际 seat、仍被按下的鼠标事件序号和拥有该事件焦点的客户端。校验失败不修改交互或窗口几何。跨客户端检查先于“已有交互”检查，避免用泛化的忙碌错误掩盖所有权问题。

输入事件与 xdg 配置共用 Smithay 的 `SERIAL_COUNTER`，避免两套独立计数器产生重复序号。序号来源和所属客户端都从实际协议对象读取；验证器同时检查真实按键、按钮及配置记录之间没有序号碰撞。

移动和缩放均以抓取开始时的指针及矩形为基准计算累计位移，反向移动不会重复累加此前变化。位置运算检查整数溢出；右下角缩放按显式最小/最大尺寸约束计算。当前场景机制不把窗口位置强制钳制到画布内。

缩放开始和后续尺寸变化发送带 `Resizing` 状态的真实配置；鼠标释放后发送不带该状态的最终配置。待确认配置及实际新缓冲提交必须完成后，合成场景才采用新尺寸。客户端普通重绘保留场景中的当前位置，不能用旧配置中保存的位置覆盖移动结果。移动期间复用原有客户端缓冲，不伪造新的客户端提交或帧回调；移动结束后另执行一次真实重绘验证此边界。

交互抓取期间指针焦点按协议离开客户端。结束时以更新后的几何重新命中并计算局部坐标，不能沿用移动前的表面原点。键盘焦点、指针焦点和交互授权是不同状态，分别验证。

## 客体负向检查

除了无效序号 `0` 和释放后复用旧序号，验证程序还测试一个仍然有效但属于另一客户端的事件序号。服务端为测试客户端继承一对真实 Unix stream 描述符 `fd=4`：A 将自己实际收到的按钮序号发送给 B，B 用它对自己的窗口请求移动，并等待真实 Wayland roundtrip 完成后回应 A。A 随后才发送合法移动请求。

该通道只用于传递授权挑战，不传递像素，不注入鼠标事件，也不替代 Wayland。验收须证明“真实按下 → 序号传递 → B 的请求 → 所有权拒绝 → A 的合法请求”的因果顺序；猜测某个固定序号不构成此项检查。

## 十二个稳定场景

128×96 画布位于实际屏幕 `(32,48)`。初始 A 为 `(8,8,64,48)`，B 为 `(40,24,64,48)`，B 在上并持有键盘焦点；指针 `(16,16)` 位于 A 独占区域。

| 场景 | 前置输入或协议行为 | A 几何 / 显示状态 |
| --- | --- | --- |
| 0 | 两客户端初始帧及无效序号拒绝 | 初始几何，B 在上 |
| 1 | A 左键按下；跨所有者挑战拒绝后合法移动 | A 置顶，抓取为 move |
| 2 | 指针 `(+8,+4)` | A 移至 `(16,12)` |
| 3 | 指针再次 `(+8,+4)` | A 移至 `(24,16)` |
| 4 | 左键释放，旧序号请求被拒绝，A 普通重绘 | `(24,16)` 保持，抓取结束；没有新增配置 |
| 5 | A 右键按下，请求右下角缩放并提交新帧 | `64×48`，Resizing 开启 |
| 6 | 指针 `(+8,+4)`，配置确认并提交新帧 | `72×52` |
| 7 | 指针 `(-4,+4)`，配置确认并提交新帧 | `68×56`，覆盖反向缩放 |
| 8 | 右键释放，最终配置确认并提交新帧 | `68×56`，Resizing 关闭 |
| 9 | Q 键，A 取消映射并实际退出 | 仅 B，键盘焦点回退 B |
| 10 | D 键，B 提交响应帧 | B 继续工作 |
| 11 | Q 键，B 取消映射并实际退出 | 全黑，窗口和焦点均为空 |

主机只注入真实 QMP 键鼠事件并采集实际 scanout，逐像素重建独立预期。每次启动的目标是 12 个场景、147,456 个显示像素、14 次输入命令、8 个客户端缓冲提交和 9 组配置/确认。每次原生画布呈现分成三个已有的有界提交，因此预期 36 次显示授权及真实完成。

## AI 与证据边界

进程、CPU、匿名页、可执行映像、共享对象及显示提交继续使用已有本地 AI 模型与资源账本。鼠标输入、事件所有权、协议顺序和位移计算属于确定性执行机制；本阶段没有新增自主窗口布局或学习模型，也没有扩大模型或内核容量。

每条并发控制台记录包含换行且不超过 64 字节，使用一次真实写入。验证器必须等待对应客户端实际就绪后再推进输入，不能把服务端显示完成等同于客户端已处理回调。

## 构建与检查入口

服务端构建入口为 `tools/build_smithay_interactive.py`，使用单独的固定源清单、fat LTO 以及已有 Mesa 静态报告；客户端入口为 `tools/build_smithay_interactive_client.py`。内核 feature 为 `smithay-interactive-probe`，分别通过 `CYXIA_SMITHAY_INTERACTIVE_PROBE_ELF` 与 `CYXIA_SMITHAY_INTERACTIVE_CLIENT_ELF` 绑定实际 ELF。它与原 LXPanel 桌面使用不同的显式镜像配置。

该镜像的串口 shell 命令是 `posix exec smithay-interactive-probe`。十二个场景是自动验收程序，完整推进需要验证器按场景发送鼠标按下、移动、释放及 Q/D 键；它不是可任意操作的桌面会话。

```sh
python3 tools/verify_smithay_interactive.py \
  --elf artifacts/smithay-interactive-kernel-r1/cyxia-kernel.elf \
  --server artifacts/smithay-interactive-build-r2/smithay-interactive.elf \
  --client artifacts/smithay-interactive-client-r0/smithay-interactive-client.elf \
  --output artifacts/smithay-interactive-manual-check --iterations 3
```

输出目录必须尚不存在，以保留每次独立运行的原始证据。
