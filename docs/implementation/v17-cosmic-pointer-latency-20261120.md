# COSMIC 光标延迟与连续移动丢失诊断

本轮已消除所测突发/持续输入的位移丢失，显著降低原来的秒级等待。完整
桌面仍有 2 / 5 项超过 500 毫秒，卡顿尚未完全消除；保留可复测镜像，
继续手动确认实际手感，不宣称达到流畅桌面或 60 FPS。

用户反馈“时钟能出现，但指针延迟明显、移动时一顿一顿”。本轮使用
`diagnosing-bugs`，先以真实输入和 scanout 截图复现，再逐项修改输入队列、
显示范围、内核读取和空桌面事件处理。编译与 QEMU 测量使用同一个原生
会话锁，串行执行。宿主为 ARM/macOS，客体为 x86 QEMU TCG，4 vCPU /
1 GiB；数据不代表物理 PC 或帧率。

## 已定位并修复的路径

VirtIO 驱动原来只发布 8 个事件缓冲。24 次 X 方向移动各含 REL_X 与
SYN_REPORT，需要 48 个缓冲。真实基线只移动 32 像素，期望为 192 像素；
截图落在 x=672，而非 x=832。实际 Queue::configure、EventQueue::prime
和 EventQueue::poll 的宿主回归也得到 `32 != 192`。

QEMU 10.2 提供 64 个输入事件槽；完整报告没有足够已发布缓冲时会被丢弃。
参见[固定版本 VirtIO input 实现](https://raw.githubusercontent.com/qemu/qemu/v10.2.0/hw/input/virtio-input.c)。
现在输入设备选择不超过设备上限的 2 的幂，最多 64 槽。仍使用原有 5 个
4 KiB DMA 页面，事件响应区最多使用 512 字节；其他请求/响应设备保持
8 槽。重复 ID、越界 ID、错误长度、超量 used 索引及错误后的终止行为
继续检查。

COSMIC 已经报告变化区域，但显示后端只检查 damage 是否存在，仍提交
整个 1024 × 768 屏幕的 48 块。去掉 session、总线、panel 与时钟后仍能
复现秒级延迟，时钟不是必要条件。现在仅提交覆盖所有 damage 的裁剪
包围矩形，包括旧、新光标区域。完整 readback 保留，源行翻转仍使用
完整图像高度。空 damage 保守回退到整屏，锁屏黑屏使用原整屏构造器。
GPU fence、EAGAIN/EINTR、超时、错误终止及 presentation 完成门槛不变。

内核原本每轮只从每个输入设备取一个事件，完整包分散在多个 OS 轮次。
现在两个设备交替读取，最多 32 轮 / 64 次 poll，无进展则提前停止。
软件缓冲仍为 128 项，单次用户读取仍最多 32 项。原丢包通知、失步恢复、
设备故障后的键释放和其他设备持键状态保留。单独采用局部显示提交时，
持续输入曾触发软件缓冲溢出；批量读取后该测试的全部位移到达。

最后，空桌面的一批同向报告原来逐项进入 COSMIC 输入处理，连续输入仍
出现约 2 秒的尾部延迟。现在只对无焦点、无抓取、没有键或按钮按住的
纯位移批次做原地合并。只有相邻、同方向、共线且相加不溢出的位移组合；
转向、反向、溢出、混合键/按钮批次均保持原序。应用焦点、拖动和锁屏
继续使用原路径。不等待更多输入，不跨 dispatch 批次积攒事件，不增加
分配。原始内核 evdev 记录不变；合并的是已解码的空桌面动作。

## 严格光标反馈回路

`tools/os_cosmic_pointer_probe.py` 通过真实 QMP 输入设备移动指针，并等待
目标位置的完整光标、旧位置擦除及中间位置无残影。初版 direct 样本曾
接受只有 71 个白像素的半个指针；最终判据收紧为固定客体中完整指针的
140 个白像素，旧样本原样保留。QMP 应答只证明宿主调用返回，不证明
客体已处理输入。

三次单包移动和 24 包无节奏突发从首个输入开始计时；96 包持续移动按
5 毫秒最小发送间隔输入，测量最后应答后的收敛时间。所有目标位置都
验证总位移。500 毫秒期限保持不变。该探针测量最终完整光标的延迟上界，
不测全部中间帧的帧间隔，也不能单凭它宣称达到 60 FPS。

以下都是实际客体数据，单位为秒。表内为 direct / no-bus 最小场景；
各阶段原始失败都保留。

| 阶段 | 斜向单包 | 横向单包 | 纵向单包 | 24 包突发 | 96 包持续输入后 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 64 槽输入，整屏提交 | 0.443 | 1.164 | 1.869 | 1.636 | 3.688 |
| 仅加局部提交 | 0.296 | 0.250 | 0.233 | 0.975 | 溢出，未到目标 |
| 再加内核批读 | 0.225 | 0.222 | 0.221 | 0.859 | 1.972 |
| 保留：再加保守空桌面合并 | 0.236 | 0.217 | 0.232 | 0.165 | 0.283 |
| 未采用：分离小区域 | 0.213 | 0.301 | 0.284 | 0.335 | 0.234 |

两种最后阶段的最小场景五项均通过期限，总位移完整；原始完整桌面基线三次移动为
0.808 / 2.344 / 3.405 秒，24 包突发只到达 4 包。原始完整场景的最终
复测结果见下节。

## 检查、构建与边界

回归都先在实际原函数上出现指定断言失败，再应用修复：

- 驱动：原位移 `32 != 192`；最终 83 项单元测试和 5 项 PCI 测试通过。
- 显示：原小幅移动提交 48 块而非 1 块；33 项实际 native cursor、像素、
  锁屏和完成规则检查通过。
- 内核 poll：原每轮交付 2 项而非 64 项，完整包未到读者；修复后 3 项
  检查通过，包括公平性、工作量上限及故障恢复。失步夹具最初没有提供
  丢弃包的终止 SYN，校正后在未改动原函数上重新获得 1 通过 / 2 失败。
- dispatch：原 24 包位移产生 24 次处理而非 1 次；修复后 23 项输入处理、
  解码和持键状态检查通过。部分 native 检查在不同夹具中重复，数量不
  应直接相加作为不同用例的总数。

`native-pointer-damage-v1` 与 `native-pointer-motion-v1` 是新版本端口，
保留精确原像、补丁、后像、GPL-3.0-only 许可证及输入摘要。没有改写
历史端口、构建器、SDK 或依赖归档。完整合成器保持锁定的 468 包依赖图、
原编译器、SDK 和资源上限。最终合成器仅在前一局部提交版上改变三个输入
处理文件，其他 128 项正常桌面输入不变。

增量构建将已验证的前一 Cargo target 克隆到独立输出，旧 target 不写入。
旧 unwind 目录作为字节相同的只读链接输入保留并再次校验。缓存复用不
代表所有包重新编译。最终构建的对照 ELF 与上一轮实际运行的对照字节
一致；两镜像的 kernel / crates / user 源码、资源配置相同，只替换合成器。

当前定向 Python 语法检查和 `git diff --check` 通过。本轮不宣称全仓 CI
通过，已有格式与跨平台 Python 缺口没有因定向检查变绿而消失。

构建、捕获、失败报告及对应 producer-inputs 不改写。

514.724 / 133.025 毫秒，面板 PID 6 增加约 372.844 / 125.562 毫秒。
