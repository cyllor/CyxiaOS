# Bounded candidate preparation before Job creation

The original normal-preparation prefix could freeze `Root.first` through `replay::first`, then leave via a model/resource/candidate/encoding exit without creating a Job or Pending. Only the queued-control-WCET retry branch previously established Pending. With no Pending, the outer retry wrapper neither accumulated this decision's preparation CPU nor retired it after a terminal error. This is a source-reproduced progress defect; the native trial-2 sequence-370 stall is not attributed to a particular one of these branches.

Before calling `replay::first`, the normal prefix now creates the existing Pending for the exact Running candidate's first unpublished attempt. The predicate requires matching boot, family, full target, no fault/initial publication, the original full snapshot if already present, and the original not-before constraint. It consumes the next sequence once. Retries use the same identity and snapshot. It does not take over an inconsistent old orphan first with a different snapshot.

A candidate marker uses existing Pending padding: old and new Pending are 240 bytes, Rejected size is unchanged, and a target compile-time bound enforces the original footprint. Existing ordinary/read-only constructors leave the marker false. No journal layout or evidence bank changes. For this candidate Pending, the outer wrapper uses its already-read timestamp to enforce the original deadline even if a later entry gate blocks preparation. Error precedence remains CPU-debit error, original terminal error, then the added candidate deadline check. Original 2 ms CPU and 50 ms wall limits are unchanged.

The actual encoding path already transfers the carried preparation cost into Job and clears Pending before returning success, so the wrapper does not debit a successful Job again. The existing rejection journal consumes and retains the original identity, snapshot, cost and error, and the Root hook rejects only a matching original captured first with no initial publication. Original nonzero Scheduler receipts and owner drain obligations remain necessary.

`before_first` Busy is explicitly different from `on_first` Busy. The former may expire before a first snapshot is captured: it records preparation retirement without inventing `Root.first` or a Root fault. This does not claim to close every pre-capture activation failure. Legitimate one-shot not-before waiting does not acquire this Pending. Baseline, published, foreign, ordinary and read-only paths retain their existing behavior.

The regression executes the actual normal prefix through the model gate, actual first/activation logic, retry wrapper, retirement and rejection journal with controlled callbacks/target-owner boundaries. Later resource exits and successful final encoding are explicit facades. Six Rust cases cover callbacks before/after first capture, model refusal, bounded retry/blocked expiry, original Stale and CPU priority, scope guards/not-before/orphan first, model drift, carried success and ordinary/read-only controls. Eight isolated negative mutations fail behavioral assertions. These host results do not prove native timing or final acceptance.
