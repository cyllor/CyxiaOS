## 反馈入口与假设

原始真实输入驱动仍为 `tools/os_cosmic_time_probe.py`，180 秒观察后完成
两轮日历开关。15 秒期限和 45 秒启动检查保持原值。新增的 debug 重放脚本
先验证实际串口及四张截图 SHA256，再检查期限；它能快速复核捕获结果，
新耗时必须重新运行客体，不能从日志重放推导。完整真实桌面循环约四分钟，
不能称为秒级反馈；没有用更快的模拟界面替代该慢循环。
测量平台为 ARM/macOS 宿主上的 x86 QEMU TCG，4 vCPU / 1 GiB；结果不
等同于物理 PC 性能。129 项桌面输入与资源上限不变。

```sh
python3 artifacts/debug/cosmic-ask-matt-perf-20261120/check_desktop_deadline.py \
  artifacts/v017-superpowers-retire-prefix-runtime-v2
```

这条已执行命令返回 1：首次打开 20.814 秒、再次打开 17.498 秒；正常渲染、
原进程存活及共享资源回收成功并不代表期限通过。

测量前列出三个可证伪假设：已封存 RX 页的重复发布预查、映射阶段重复逐页
检查、以及用户态渲染/调度。先验证第一项，每次只更改同一个预查路径。

独立观察二进制记录 8818 页 RX 发布的逐页封存查询为 17,654 次：发布预查
8818 次，映射验证另外 8836 次。普通计时二进制不启用观察计数器。
新增性能断言在原版实际失败；首次观察夹具的链接错误单独保留，未把编译
失败计作性能红灯。

## 最小改动及回归范围

`PhaseTable::all_sealed` 对覆盖的每个 64 位权限字块执行一次 Acquire 读取。
一个字块存放 32 页的两位状态，按覆盖范围掩码精确匹配 `10`；RW、Transition
与保留编码 `11` 都不能当成封存。检查完整覆盖、整数溢出、首尾部分字块；
不保存上一次查询结果，也不替代所有者、alias lease 或硬件 fence。

桌面 `publish_code` 使用经过物理范围校验的范围查询。长度向上取整只是为了
保留原预查的“逐个页起点”行为；未封存时仍将原始长度交给现有 seal 事务，
因此部分页的错误边界与零长度行为保持一致。逐页映射验证、alias 计数、
Transition 隔离、实际 PTE 写入与 TLB/IPI 协议继续执行。

新增用例检查字块两侧污染、任意单页 RW/Transition、保留编码、空表及
溢出，并在实际发布包装器中检查 512 页状态变化后重新校验、封存 fence
失败、RAM 最后一页及部分长度。宿主夹具替代的是 CPU 身份、物理背衬和
PTE/TLB 硬件边界，实际权限表、包装器、alias 核心和封存事务来自源码。

## 已定位的后续热点

本轮基线的四次交互间，七个原存活进程合计重建地址空间 21,972 次。
合成器 PID 3 为 4086 次、累计构建 7.449 秒；面板 PID 6 为 7187 次、
10.359 秒；二者占累计构建 HPET wall 的约 78.5%。这是按两个实际
`posix list` 之间的差值分析，含宿主调度影响，不是 CPU 计费或单次尾延迟。
进程身份由同次捕获的启动命令、SPAWN_CHILD 父子关系核对，详细差值保存在
`baseline-process-costs.json`。

重复构建仍值得继续测量。根复用需要同时处理映射变更、W^X、CPU 驻留、
shootdown 与 backing/alias 回收；本轮只更改封存预查，没有引入此类生命周期
变化。第二、第三个假设尚未通过独立变量实验验证，不能当成已证实根因。
