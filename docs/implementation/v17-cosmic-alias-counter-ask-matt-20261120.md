## 被测改动

`mapping_change_locked` 在已持有 alias writer lease、完成物理覆盖及新映射
phase 校验后，读取原有 64 位计数。如果其精确等于旧 flags 对应的三个
0/1 计数字段，则每次减去旧 alias 后三字段必定全零，增加新 alias 后每字段
最多为一，可直接写入新 flags 对应的计数。共享、多引用、异常字段及边界
计数继续使用原来的三字段 checked-sub/checked-add 算术。

这个等式需要匹配整个计数值。高位保留位不匹配时继续走原路径，以保留原本
“成功清除保留位、失败不改原值”的行为。计数下溢时即使新旧 flags 相同也
必须失败，不能只看净差值。旧新计数的 Acquire/Release、writer lease、CPU
认证、逐页物理/phase 校验、成功前缀、页表写入及 fence 均保持原样。

新增实际 runtime 回归使用独立的有符号字段算式，对 RW/Transition/RX、
全部旧 flags、合法/非法新 flags、0/1/2/最大值附近及保留位组合逐项核对
结果和失败后原计数；另检查独占、共享、多次删除及 Transition 下回收。
这些是宿主硬件边界夹具中的实际生产函数，不是 QEMU 或物理 PC 的 MMU
验证。性能观察计数器只加在独立的观察二进制，正常计时二进制不启用。

## 先红后绿与当前检查

在归档原版上执行新增 48 项实际 runtime 用例，正确性通过；独立观察版本
在 8 页映射/回收各执行 8 次通用字段算术，要求为 0，实际断言失败。
改动后相同 48 项用例和工作量断言均通过。60,000 组独立算式组合位于其中
一个用例内，不能把它们另外算成 60,000 项测试。

48 项实际 runtime 用例和候选镜像 `OS_NATIVE_PASS` 均通过。初次 Cargo
架构检查复用了回退前的旧测试产物，其 293 项结果不算当前源码的检查；

“当前源码架构检查通过”的聚合证明。
