# V0.20 eight-role integration — source audit and release blockers

Scope: source audit of PR #78 head `2b517065c624640f4aa7dbbf35ce922b0b523cd7`, with targeted fail-closed corrections on a separate descendant branch. The normative baseline is `docs/design/baselines/v0.19.9-implementation-spec.txt` (§2.2, §6.1, §8.0, §9.6–10); `docs/design/v0.20-native-local-system.md` carries the V0.19.10 snapshot candidate. The historical ABI v1/dynamic-control-core prototype is not the target for this audit. All 15 current local domains retain equal architecture standing. No cluster/D16 or dynamic control-core expansion is introduced.

## Corrected source findings (new regression execution required)

| Audit ID | Defect and correction | Source / regression |
|---|---|---|
| AR-01 | Causal disposition must bind the exact candidate-set hash of the decision, not just the hash of the supplied decision bytes. Explicit adopted-recommendation comparison is retained as defense in depth. | `advice_disposition_v1.rs`: `matches_decision_pair`; `causal_pair_denies_relabelled_resource_generations_and_expired_decision`, `adopted_disposition_requires_current_ai_decision_and_matching_advice_key` |
| AR-02 | CONTROL_AUX cannot finalize decision-bearing states 1/2. Only the independently checked registration path may freeze ADOPTED; state 2 remains closed until the atomic reason7 fallback gate exists. Terminal advice cannot be read as newly admitted advice. | `advice_ledger_v0199.rs`, `registered_gate_v3.rs`: `assisted_advice_is_not_authority_and_exact_disposition_and_model_are_rechecked` |
| AR-03 | A terminal digest alone cannot recycle a 512B evidence slot. `consume_verified` requires an independent EL1 custody verification of the exact advice/disposition and linked DecisionRecord where present. Verification failure retains the slot and high-water. This is a component callback contract, not a native audit-storage implementation. | `advice_ledger_v0199.rs`: `bounded_advice_slot_is_never_a_capability_or_replayable_after_ack`; assisted registration regression |
| AR-04 | A historical BootEpoch/service commit receipt cannot return success while a different persistent change is pending or UNKNOWN. Exact retries of the current prepared transition retain its identity; historical successful outcomes outside an active transition are not startup authority. | `durable_role_epoch_v0199.rs`: `only_exact_stopped_slot_generation_changes_and_isolation_cannot_be_cleared`, `boot_unknown_preserves_exact_after_image_and_never_burns_second_epoch` |

These are local reference-component corrections; unit-test assertions and source review are not execution evidence. The independent EL1 callbacks must be wired to actual native owners before production authorization.

## Release rule

Do not merge as completed production G0. Record each mandatory case as PASS, FAIL or NOT_RUN with exact commit, image/model/schema hashes, command, raw trace and independent checker. A historical or diagnostic PASS may not substitute for real service behavior, authoritative receipts, persistent recovery, or the full formal acceptance matrix. New audit changes must receive their own component test and native evidence; prior CI runs are not evidence for this branch.
