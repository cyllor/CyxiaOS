# CyxiaOS 原生双节点集群：安全核心代码增量

## 范围与基线

代码基线为 `desktop/native-wayland-pipeline-20261023@e7a40fccb653a30c4b92f4f644962d0a0dc31e7c`，接续已交付的 `control_plane` 模块。本包不改桌面功能，不启动后台下载，也不提交或推送仓库。

本轮交付的是可在 `no_std` 环境编译、无动态内存分配、禁止 unsafe 的确定性集群状态机。它支持固定两个原生成员的初始建群、相同成员的更高配置纪元重加入、资源合同、最终操作端 fencing、任务启动去重与对账，以及有界副本写入确认。它不是已经运行的网络集群，不是 Raft/自动选主实现，不是复制文件系统或透明进程迁移。

设计依据为项目库的《CyxiaOS_原型统一实施主规范_第12至21轮递归审校修订》第 2、11、12 节及《CyxiaOS_原型自治集群_协议级复核修订规范》（原文件 SHA256 见 prototype-requirements.json）及既定原生成员、双平面隔离约束。只有原生 CyxiaOS 内核、系统服务、本地 AI 与真实物理核心隔离证据都满足准入，才能成为正式成员。宿主 Linux/macOS 测试进程不是正式节点；Android/iOS/Windows/Linux 兼容代理不可成为投票或持久副本节点。

## 新增模块

| 模块 | 可执行逻辑 |
|---|---|
| `boot` | 在广告身份之前通过持久化 CAS 分配 BootEpoch；响应丢失后重读再递增，禁止回绕。 |
| `auth` | 固定协议、原生身份字段、物理核心集合不重叠、必要能力校验；接收方绑定的新挑战、签名验证和可信原生启动授权接口。 |
| `membership` | 固定两票配置、确定性成员排序、FormationID/ConfigDigest、双方提交证明及多阶段激活。隔离保留 ClusterID，恢复不自动恢复共享授权。 |
| `admission` | 复用原控制面 `Bank` 的已验证策略，独立检查 CPU、内存及 I/O 需求；远端没有本地 CoreOwner 写接口，不同步等待模型。 |
| `contracts` | 有限期预留、持久化 grant intent、fence 安装后才授予、排空后释放；重复 ID 幂等、不同内容冲突、保留终态去重记录。 |
| `endpoint` | 最终操作端精确 token 匹配、OwnerNode 本地绝对期限、在途引用计数、持久化撤销及真实后端排空证明。 |
| `tasks` | 任务/激活代次/操作 ID/负载摘要绑定；实际启动前重新验证，Running 先持久化，重复请求不再次调用执行器；未知结果进入 Uncertain。 |
| `health` | 本地期限绑定的挑战应答；迟到回包不以到达时间续期；失败只隔离，不改票数、所有权或 ClusterID。 |
| `wire` | 精确长度、版本、保留位、消息类型、收发方、启动代次、配置、会话 nonce、序号及签名验证；错误签名不推进水位。 |
| `replication` | 实际有界数据与元信息持久化后才给出待签 ACK；同一版本禁止冲突写，两名不同原生成员及要求的故障域签署同一写入后持久化提交回执。 |
| `storage`、`codec`、`mod` | 版本化有界编码、持久化 CAS 契约、公共类型、额度溢出检查和单调时钟保护。 |

## 精确的状态与成功含义

成员激活顺序是：

`PREPARED → PROVED → ACTIVATION_READY → ACTIVE_MEMBER → ACTIVE`

PREPARED 已持久化后，服务才得到允许签署的确认字节；双方签名验证、证明持久化之后，仍无共享资源权利。双方先持久化激活准备并签 READY；双方 READY 都有效后，各自持久化 ACTIVE_MEMBER 并签 ACK；取得两个 ACTIVE_MEMBER ACK 且本地 ACTIVE 成功落盘后，才能取得 `Active` 借用视图。该视图仅允许协商，不能直接启动任务或执行共享写入。重载 ACTIVE 快照也不会立即返回该视图，必须重新认证，并以更高激活纪元完成握手。

合同顺序是：

`RESERVED → GRANT_INTENT → [端点安装 fence] → GRANTED → REVOKING → [确认排空] → RELEASED`

预留要同时满足已有 AI 策略、本地实际容量、成员代次、目标 ISA/ABI 与原始期限。已经提交的合同不会因为模型故障或策略过期被当作“未发生”。租约到期阻止新操作，但不是在途 DMA、设备写入或进程已经停止的证据。释放需要 `DrainBackend` 对真实目标证明排空；接口不提供默认成功实现。不能 fencing 的目标拒绝自动接管。本包没有实现跨节点所有者迁移，也没有用超时替代它。

任务先持久化 Running，再获取最终执行许可并调用真实 Executor 一次。重复激活只查询状态。启动返回 Unknown，或重启时发现 Running，都不触发自动重跑；必须查询实际执行/设备状态。该机制不承诺任意外部副作用的恰好一次。完成和释放不依赖当前模型、连接或成员活跃状态，但仍必须满足原合同和真实完成证据。

## 持久化、时钟与可信边界

`Store::replace` 的成功必须意味着原子、可恢复、已持久化的完整记录，且 expected revision 比较成立；不能把排队、网络 ACK 或易失缓存当作成功。任何不确定的写错误都会使持有状态的对象进入拒绝新授权状态。恢复必须从可靠存储重建，不能继续使用旧 RAM 中的 revision。BootEpoch 和成员历史还要求防回滚存储与可靠身份生命周期；本包没有实现这些硬件保障。

所有时间单位为调用方提供的单调 ticks，同一调用链必须统一频率。合同的 reservation_until、lease_until 在 OwnerNode 的 BootEpoch 内解释。接收方不把发送方时钟当成本地时钟，也不通过收到旧消息重新计算 TTL。全局时钟同步、时钟漂移证明和跨节点租约转移不属于该增量。

Crypto 必须由受审查的 SHA-256、严格签名验证和可信启动/配对授权实现。签名为 64 字节、NodeId 为 32 字节，适合接入选定的 Ed25519 套件，但本包没有给内核增加一个伪密码实现。`authorize_native` 必须验证真实原生启动和隔离证据；仅签署“我是 CyxiaOS”的自声明不够。测试中的可信测量允许列表不是真实远程证明。

所有管理对象由单个序列化 EL1 管理者持有；模型和网络输入只能经过验证入口传入提案，不能直接构造 kernel Environment、调用 Store、操作 Ledger/Endpoint 或伪造 DrainBackend。生产集成必须把真实 CPU、进程身份、权限、时间和资源账本传入。`Active` 的借用和不公开的许可构造器防止普通安全 Rust 调用者误用，但不把已被攻陷的 EL1 排除在信任根之外。

## 容量和协议边界

固定两个投票成员，新增/替换成员、正式离群和三节点以上多数派变更尚未实现。两个节点必须都确认写入；分区后没有“剩下一节点即多数派”的分支。

每个合同账本和任务账本至多 8 个条目；终态保留、不自动复用，用满后拒绝新 ID，避免忘记去重水位。默认测试使用 4 条目。最终端点在途操作至多 64 个，测试配置为 4。编码缓冲为 8192 字节，网络负载及单个副本数据至多 1024 字节。扩大这些容量需要审查栈空间、持久化记录和模型资源输入域，不能通过删除校验完成。

网络帧为：magic `CYXNET01` / u16 version / u8 kind / u8 reserved=0 / Scope / sender incarnation / receiver NodeId / session nonce / u64 sequence / u16 length / payload / 64-byte signature。整数为小端，所有固定数组按原字节序，不允许尾随字节。签名覆盖全部头和负载。不同签名用途分别使用带版本的 domain separator。会话 nonce 要求经过认证握手的新 CSPRNG 值；该 framing 本身不提供加密、网络发现或重传可靠性。

副本数据按 cluster/resource/version 构造不可变键。后续未提交版本不会覆盖此前 ACK 覆盖的数据；本轮不实现垃圾回收。最终提交还需持久化本地回执。它是有界对象的协议与存储接口，不是完整复制文件系统，不提供完整产品级 RPO/RTO 承诺。

## 测试与未验证项

统一执行器记录源文件 SHA256、工具版本、命令、退出码、日志 SHA256 和 NOT_RUN 范围。Rust 测试直接导入实际新增模块；控制面回归使用上一包的原样源文件。大多数故障测试使用明确的内存持久化替身与非密码测试签名，覆盖写前失败、写后响应丢失、分区、过期/旧 epoch、任务不确定执行、资源计数和坏数据。另有实际 OpenSSL SHA-256/Ed25519 测试，以及 `write + sync_all + rename + 目录 sync_all` 文件测试适配器；这些证明主机函数调用与重载，不是断电硬件持久性或原生客体身份认证。

尚未接入：原生 NIC/网络发现、内核密码与密钥库、原生持久事务后端、实际测量证明、真实任务启动/设备 fence 后端、多节点选举/成员变更、检查点传输/restore、自动接管、双原生 QEMU 集群、物理控制面隔离。所有对应完成标志必须为 false/NOT_RUN。现有内核 CPU0 启动和同步 AI 路径不会因增加本模块而自动改变。


## 2026-10-24 审核修复：授权、重放和不确定状态

`Endpoint::begin` 现在必须同时收到当前 `Ledger`，再次验证精确 token 对应的合同为 `Granted`。仅安装 fence、已经进入 `Revoking`、恢复后尚未对账或账本写入结果不确定时，均不得开始新操作。`Ledger::commit_grant` 的低层 fence 检查仍不等于资源授予；只有完成持久化授予，最终执行入口才可通过。任务启动入口已同步接入，完成和排空路径不依赖新 AI 策略。

新合同不仅验证单次需求，还按本地授权 subject 汇总所有未释放合同，再检查 AI 允许预算和物理总容量。该汇总不是实际 CPU 时间或 I/O 字节计费：原生运行时仍须强制执行 quota。`Book::query`、`Ledger::used/status` 在不确定存储失败后返回 `Reconcile`，不得向调用方输出陈旧 RAM 状态或偏低额度。

成员持久记录版本升级为 **2**，保留最多 16 个 FormationID→ConfigDigest 绑定。不能给同一 FormationID 再签不同配置；历史绑定跨重载保留，用满后拒绝新事务而不是遗忘旧证明。替换待处理配置必须先经过明确且已持久化的 `Isolated` 边界；后续新配置仍需双边签名/激活。新的 formation 要使用新的可信 nonce。

提交回执持久记录版本升级为 **2**，保留最多 16 个提交版本的 operation_id、写入身份及双边 ACK。更早的操作也不能在中间夹入其他提交后重新执行；完全一致的旧请求返回已有结果。槽位满后拒绝新版本，尚未实现可安全遗忘历史的日志压缩/GC。

**兼容性警告：**旧成员记录和旧提交记录版本 1 没有完整历史。加载返回 `Error::Version`，不自动初始化、不推断历史、不删库重建。这两个记录类型的生产升级必须单独实现带证明的离线迁移/对账；本次未交付迁移工具。其他记录类型的版本未改；网络签名格式本轮未变。状态机主机测试不证明旧原生镜像可以无停机升级。

本轮修复测试、整机剩余缺口、规范歧义及可执行证据清单见 `prototype-gap-review.md`。正文历史测试数字仅描述原增量；新测试结果以本轮独立收据为准。
