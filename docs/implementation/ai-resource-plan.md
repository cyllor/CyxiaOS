# AI 内存、进程、设备管理实施计划

用户授权：实现 AI 强化的内存管理、进程管理、设备管理。保留当前未提交的 Shell/文件系统工作，在其上递进。

## 本轮可运行边界

- 内存：独立 32 页（每页 4096 字节）真实 RAM 页池，局部整数模型控制准入；沿用 kernel-core 授予账本，校验所有者、容量、句柄、清零、退出回收。不提供任意物理地址读写，不宣称已实现用户虚拟内存、换页或全 RAM 动态分配。
- 进程：8 个有唯一身份的协作式 EL1 内核任务，内建 compute/memory/uart 工作负载。创建、就绪、等待 I/O、暂停、恢复、结束、回收；本地模型选择就绪任务及有限工作额度。实际执行计算、页内存读写、驱动 I/O。不是 ELF 装载器或独立 EL0 地址空间。
- 设备：注册 UART 和定时器（由真实平台启动信息确认），系统控制台/计时中断属于固定保留；AI 控制普通任务的有界异步设备请求队列。含设备在线/离线、禁止关闭关键设备、请求身份、取消、重试上限、完成唤醒和退出清理。无未接入硬件的虚构“支持”。
- 模型：三个资源域使用可复现合成数据训练的整数参数。所有推理在客体内执行；固定模型版本与逐动作来源记录。沿用文件域学习能力，新增模型先固定发布，不宣称已经在线自学习。
- 跨平台：可移植 no_std 管理逻辑与 DeviceIo 驱动接口分离；单一 Runtime 所有者，CPU0 调用。多核后续每域以同一提交权威串行化，当前不宣称 SMP 安全或启用多核。
- 预算：管理服务独立静态预留上限 256 KiB（含 128 KiB 页池）；控制台/文件服务原有预留独立计算。每个主循环至多一次任务派发、一次设备请求尝试；任务执行最多 256 个工作单位。时钟单调检查，不无限补偿错过的 tick；不以协作步数冒充抢占式时间片。

## 验收

- 单元测试容量总账、所有者/陈旧句柄、清零、非法/过期动作、任务状态迁移、退出回收、设备失败/取消/阻塞/唤醒、模型对排序产生实际影响。
- QEMU production 开发/优化版实际 Shell 命令测试；任务真实完成并产生校验和、内存字节与 UART 标记；保留文件系统与 M1 回归。
- 检查模型可复现、Rust 格式/clippy、无 FP/SIMD、内存布局。
- 按 requesting-code-review 技能执行独立最终审核并修复重要问题。

## 执行状态
