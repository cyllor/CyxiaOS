本报告仅记录 M1 基线；后续已实现 [Shell 与 AI 文件系统切片](shell-ai-fs.md)，不改变以下历史验收范围。

日期：2026-10-15。状态：**KERNEL_BASE_READY**；AI 状态：**NOT_IMPLEMENTED**。

代码位于项目本地 `m1-kernel` 分支。原设计、浏览器原型和历史审核快照均保留。

## 已交付

- Rust no_std workspace 与架构/板卡/驱动分层；通用逻辑不依赖 MMIO 或模型运行时。
- AI 决策来源与检查式身份；资源授予、容量/元数据/兑现编号预留、取消与防重放释放。
- 有界 DTB 解析、裸机 EL1 入口、内核高地址映射、低地址撤销、W^X 和栈保护页。
- 页所有权/撤销/清零机制及真实客体页内容自检；尚无用户内存服务。
- GICv2、物理定时器、异常上下文保存、WFI、未知 IRQ 屏蔽。
- CRC 校验日志、有界 QMP 测试、独立内存进度、日志覆盖检测和进程清理。

## 实际验证

`python3 tools/verify_m1.py --output artifacts/m1-final`：**22 项检查全部通过**。

- Rust 主机测试 34 项；Python 测试 26 项。
- 格式、主机/裸机 Clippy、依赖方向检查通过。
- 开发版和优化版分别通过 ELF 检查、无 FP/SIMD 指令检查、启动/页/异常/IRQ 组合测试以及日志停读压力测试。
- 无 selftest 的优化映像通过启动；不导出测试进度符号，不注入保护故障/SPI，也不触发日志压力。
- 内核装载跨度：开发版 2760704 字节，优化版 2748416 字节，低于 16 MiB 目标。
- 主机可测逻辑 LLVM 行覆盖率 **91.68%**；不包含汇编、MMIO 驱动与客体内核，不能代替 QEMU 或实体硬件验证。重跑：`python3 tools/coverage.py`。

## 独立审查与修复

一次独立全分支审查发现 3 项 Important，0 项 Critical，未列 Minor。三项均先用回归测试复现失败，再修复，最后重跑完整验收：

1. ELF 零内存段绕过尺寸检查 → 先检查 filesz≤memsz，才允许跳过空段。
2. 压力采集末尾的 FAIL 帧可能被误判通过 → 最后一次解码后再次检查客体失败。
3. 授予未预留兑现编号空间 → 提交时同时检查全部未兑现承诺的最坏编号需求。

这不是全操作系统无缺陷证明，也不改变 v0.7 历史文档审核结论。

## 实施裁定

- 直接在用户指定项目目录的新本地分支实现；没有独立 checkout，保持 VSCode 路径。
- 磁盘不足时复用本机已安装的 Rust 1.95.0 stable；doctor 强制版本检查。未来 stable 升级须重新配置或验收。
- 安装等待期间先执行同版本主机逻辑测试；裸机验证在组件安装完成后进行。计划提取脚本不识别 T 前缀标题，直接使用原计划和执行记录。
- 撤销回执为明确 unsafe 的可信机制边界；未来 M2/M5 必须连接真实能力、页表撤销和 DMA 同步，调用者虚假声明仍会破坏保证。
- M1 每个独立 QEMU 会话使用 session=1，由 run-id、映像哈希及独立 socket 分隔；尚不支持多启动日志直接合并。
- 固定 virt 启动映射先于高层 DTB 解析；硬件使用前验证板卡几何。新板卡需新适配，不能直接沿用地址。

## 未实现与验证边界

本地 AI 推理和学习、EL0 应用、任务/进程服务、文件系统、网络、SMP、第二架构与实体板验证均尚未实现。真实物理页映射撤销、DMA 和硬件缓存一致性不在本次证明范围内。主机覆盖率不证明汇编/设备行为；QEMU 结果不证明实体硬件时延、安全或功耗。

下一阶段为 M2：EL0、静态任务装载、能力和 IPC；后续 M3 才接入真实本地 AI CPU 模型。正常资源策略必须继续遵循 AI_DIRECT/AI_PLAN 契约。
