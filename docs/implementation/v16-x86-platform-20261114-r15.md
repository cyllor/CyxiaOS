# R15：x86-64 平台实现与多架构解耦

日期：2026-11-14。基线提交：`208cd29db8f79533b893ca040f5faa1ebfd5cd23`。

实现及使用命令见 [x86-64 平台说明](x86-64-platform.md)。本轮完成 PC 平台机制和
共享边界拆分，未完成 x86 SMP、生产调度、设备/桌面、A03/A10 验收链移植。

## 实现

1. `arch-x86_64` 承担启动、分页、GDT/TSS/IDT、异常与用户态切换；
   `platform-pc` 承担 Multiboot、16550、PIC/PIT。
2. 内核入口、Cargo 依赖和构建脚本按架构选择；原 ARM 入口与构建体移入独立文件。
3. `FramePool::from_memory` 接受通用 RAM/保留区，两个架构复用同一页框自测；
   `prototype` 的硬件 SHA 请求通过中立 `arch` 门面，软件 fallback 保留。
4. 公共 ELF64 解码、源码/缓存身份、native lease 从平台工具中抽出。
   x86 producer 的 Python 导入闭包为 6 个文件，不包含 ARM 验收脚本。

## 发现并处理的问题

- 优化版的全图 LTO 混合 `small` 和预编译 `core` 的 `kernel` 代码模型失败。
  x86 target 增加 `-C lto=off` 后开发/优化版均通过；ARM release 配置不变。
- 修正 `int3` 不适用的 `nomem/nostack` 声明；按 64 位硬件帧保留完整 176 字节陷阱布局。
- 公共 ELF 符号解析需允许同一零尺寸符号在相邻段边界对应同一地址；去重仅限同一符号
  记录，实际重复条目或不同物理映射仍拒绝，新增 3 项回归。
- 工具公共模块使两条旧闭包数量断言变化，更新为精确集合并增加共享文件哈希变更检查。
- 一组历史测试引用的临时源码目录已不存在。从保留的 R7 源码副本恢复 3 份 schema 文件，
  逐字节 SHA-256 与 R8 上下文一致；没有修改历史上下文、磁盘或原 FAIL 结论。
  恢复记录为 `restored-historical-schema-fixture.json`，该目录不是完整源码 checkout。

ARM 全目标严格 Clippy 仍被两处原有 `policy.rs` 告警阻断：`misnamed_getters`（第 91 行）
和 `too_many_arguments`（第 1569 行）。已与基线比较，相关实现没有变化；该检查明确不计 PASS。
ARM 编译与真实 VM 回归独立通过。

## 验收边界

最终有效的 x86 证据为名称含 `-v2` 的目录。前一次开发版使用旧源码清单，优化版保留了
失败日志，均不作为最终代码的通过证据。旧 A03/A10 证据也不能重新标记为本次源码的 PASS。

当前只验证 macOS ARM 宿主的 QEMU TCG：PC 单 BSP、256 MiB。Linux KVM、实体机、
64 核客体与 128 GiB 内存没有实测。`X86_PLATFORM_SELFTEST_PASS` 不改变 A01–A16 状态。
