## Scope and engineering decisions

- T27 D08 service capability lookup: retain the actual capability table in increasing issued-ID order, compact occupied prefix and empty tail. Lookup and append-position search O(log N); bulk and single revocation O(N) with bounded compaction. No second index, no ID reuse, no change to rights, owner, generation, revalidation or per-item completion. More movement on revocation is an explicit trade-off. This is the existing prototype service mechanism; no claim of full native ABI deployment.
- T28 D10 ordinary TX: construct a turn-local 16-bit ready mask once, select in existing cyclic order by rotated trailing-zero scan. O(N+B) inspection/selection versus O(N*B), excluding transport calls; N=16, B<=16. No persistent duplicate state, same cursor advancement on backend errors, same reserved service and custody semantics.
- T29 file receipt structural validation: decode each occupied record as before, then sort the bounded canonical ID prefix and detect adjacent duplicates. Equal full keys imply equal canonical local IDs after successful decode. Same rejection across retained generations; no change to CRC, stream/index validity, journal, media or persistence ordering. Worst-case uniqueness O(N log N) rather than O(N^2). Adds 1024 bytes of explicit local ID scratch plus bounded sort call stack; target stack headroom remains to be verified.
- T30 IRQ timing histogram: checked u64 multiplication and exact ceiling division when possible; wide fallback on multiplication overflow. Nearest rank is count - count/100; checked u64 cumulative sum rejects any inconsistent/overflowing histogram, as the previous count-conservation check did. Keep atomic ordering, bin bounds, writer protocol, reader retries, count/tick accounting, and unavailable p99 behavior unchanged.
- T31 verification: extend to 21 nonempty module jobs and retain format/default workspace gates. Add exact-commit AArch64 production-skeleton build (including existing fixture guest build) and x86 platform fixture build using repository-pinned commands. These are cross-build evidence, not QEMU/physical hardware or G4/G5 acceptance. No changes to kernel default features.

## Evidence and limits

Executed deterministic JS reference-model comparisons: capability state 120000 transitions, network 262144 mask/cursor cases and 16000 multi-step cases, receipt 18000 ID sets, IRQ 30000 arithmetic/rank cases and 30000 extra bucket cases; all matched. Total 476144 checks across heterogeneous models, not Rust execution or timing evidence. The first staged network edit was refused by the exact-source seam check; re-read and corrected the match, with no branch mutation. Four new Rust interface regressions exercise capacity and revocation, sparse rotation/error retention, full receipt store with duplicate generations, and IRQ overflow boundaries. Local rustc/cargo/rustfmt unavailable; full Rust RED/GREEN not executed locally. Behavioral-equivalence tests need not fail on the old implementation; performance acceptance requires separate benchmarks. Same-agent source/spec review only. Actual CI results pending.

Ruling: do not introduce new authority, scheduling policy, wire format, persistent state or cluster mechanisms. Preserve fixed CPU0, separated advisory brains, existing equal subsystem architecture status, and native local execution. No merge or release claim.
