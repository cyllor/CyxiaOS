# V0.17 x86 多核、执行计量与完整运行时设计

状态：待用户审阅的实施设计。基线为 `CyxiaOS-V0.17` 的 `e5369c5`。
本文细化 [平台设计](../../../CyxiaOS-v0.17-platform-design.md)，不宣称已有 x86 原生 A03 PASS。

## 目标与范围

用户要求补齐 x86 多核、计量和完整运行时，并继续推进 A03。
最终交付是在真实 x86 客体中复用现有统一运行时，运行受保护普通任务、持久文件、网络与双节点
服务，具备真实执行计费和控制核心所有权迁移，再接入真实数据、自举训练及普通需求 A03。
四核启动、模型能编译、独立小调度器或平台日志均不能单独代表这个目标完成。

首个运行配置固定四 vCPU、1 GiB 客体 RAM、QEMU 10.2.2 的 `pc-i440fx-10.2`。
保留现有单 BSP / 256 MiB 平台 profile；Linux x86-64 是主开发宿主，当前 macOS ARM 可运行 TCG 回归。
桌面移植、64 核客体、大内存扩展、热插拔、固件泛化与实体机认证不属于本轮完整运行时的含义。
ARM 兼容路径和历史证据继续保留。

## 实现路径与取舍

平台方向和复用共享策略已由用户确定。本设计的具体实现选择由开发者提出，等待本文件确认：

- 复用现有 Coordinator、任务/预算、文件、学习与集群逻辑，提取 CPU、页表、用户切换、时钟及设备接口。
  这条路径保留行为与验收依据，但必须处理现存 ARM 汇编、页表和 ABI 耦合。本设计采用此路径。
- 独立开发一套 PC 精简运行时能较早展示多核任务，但后续还要重做既有计费、持久化和训练语义；
  不满足本次“完整运行时”及已有多平台解耦要求。
- 仅将共享库交叉编译并扩大平台自测，改动较少，但不能运行 A03 的真实普通任务与训练链。

执行计量先移植已有 TCG 翻译块执行时间机制。KVM 是独立后端：在没有经过验证的执行计量源前，
KVM 仍可运行机制自测，但必须拒绝依赖执行计费的完整运行时/A03 profile。
这会延后 KVM 性能加速的交付；不能把 KVM 的 TSC 时间当作计费证据来消除这个缺口。

## 已确认的实现缺口

1. `kernel/build/x86_64.rs` 拒绝 `smp-selftest`、统一运行时及学习 profile。
2. `interrupts.rs` 的 GDT/TSS/IDT、用户态返回栈和部分探针状态是 BSP 全局状态。
3. 最终页表只映射低 256 MiB，未映射 LAPIC；当前内核从 1 MiB 开始，和服务用户地址重叠。
4. ARM 计量使用专门修改的 QEMU PMCCNTR。现有 x86 QEMU 没有相应能力或来源认证。
5. 共享 ELF 验证器仍固定 ARM `e_machine=183`；运行时直接操作 ARM 页表和异常状态。
6. VirtIO 队列可复用，但 `Transport` 当前是具体 MMIO 寄存器实现，PC 需要 PCI 传输。
7. 统一运行时有六个基础用户映像需要目标适配：runtime、learning、governance、task、client、cluster。
   memory-client 属于额外 A09 诊断；另两个独立控制自测映像和桌面不计入 A03 必需集合。

## 分层及接口约束

- `contracts` / `kernel-core`：逻辑 CPU 身份、单调时间/执行计量类型、映像 ISA、页权限、所有权和预算规则。
- `arch-x86_64`：CPU 寄存器、AP 入口、描述符、用户上下文、页表与 TLB 机制。
- `platform-pc`：ACPI/PCI 发现、LAPIC/IOAPIC 板级接线、时钟设备、VirtIO 设备描述。
- `kernel/src/composition`：选择共享运行时和真实平台适配；业务模块保持单份实例。
- `kernel/src/runtime`：既有任务、控制、服务、持久化、网络及学习实现。

共享业务不接收 ARM ESR/异常帧或 x86 TrapFrame。用户退出统一描述为系统调用、抢占或访问故障，
并携带明确的调用号/参数或访问类型；硬件寄存器编排留在适配层。
地址空间接口拥有建表、映射、切换、撤销、代码可见性及跨核失效的责任，不能只给 ARM descriptor 改名。
执行计量戳包含逻辑 CPU、来源 ABI 和累计执行纳秒；跨 CPU、倒退、来源变化和溢出均报错。

## 多核启动与停机

从 ACPI RSDP/RSDT 或 XSDT/MADT 读取实际处理器和 APIC ID，建立 BSP 在 slot 0 的逻辑映射。
校验校验和、地址范围、长度、重复 ID、启用状态、容量和 BSP 唯一性；不使用 CPUID 数量猜测 APIC ID。
首版仅支持 xAPIC；遇到启用的不可支持拓扑则明确拒绝。

在最终页表移除零页前读取 BDA/EBDA 所需信息。低地址 trampoline/mailbox 必须属于经验证的可用 RAM，
避开 Multiboot、映像、EBDA 和固件保留区；分别为 supervisor RX 和 RW/NX。
AP 使用独立 16→32→64 位入口，不清 BSS、不复用 BSP 栈、不重建共享页表。
邮箱提供最终 CR3、私有栈、逻辑 slot、APIC ID、入口与代次；逐个启动并等待软件上线确认。

每核有独立 GDT/TSS、内核栈、用户陷阱栈、double-fault IST 和不可访问保护页。
LAPIC MMIO 使用 supervisor、不可执行、明确 UC 的映射。INIT/SIPI、IPI 发出与等待都有界；
启动延时使用明确的板级时间源，不假定 TSC 频率。

STOP IPI 仅发出请求。收到 IPI 或完成 ICR 投递不等于停机：调度安全点关闭旧工作的准入，
完成或保存当前用户上下文，释放旧引用并确认 TLB/中断状态后，才能发布带代次的停机 ACK。
验证至少两轮 stop/resume，确认停机后旧进度不再增长、旧 ACK 不能满足新请求。

## 独立执行计量

在新建的 QEMU 源码/构建目录复用现有 `tcg_qemu_tb_exec()` 前后计量和 longjmp 收尾。
计量包括翻译后客体指令及同步 helper，排除翻译/JIT、退出 TB 后的事件工作、休眠和兄弟 vCPU。
保留现有 ARM 源码及二进制不变，为 x86 建立独立补丁、源码摘要和运行来源验证。

新能力由带项目标识、版本、单位和专用只读 MSR 编号的 CPUID 叶公开。
仅在 MTTCG、当前 vCPU、线程时钟有效且计量状态健康时公开；初始化失败、倒退、溢出或后续读错
锁存故障，禁止无声丢失计费区间。MSR 写入拒绝，读取失败触发明确故障。
每个 CPU 先验证完整能力再读取；缺能力时普通平台自测仍可运行，计费运行时拒绝启动。

单调时间负责 deadline、租约及窗口，执行时间只负责 CPU debit。两者独立表示、转换和验证。
计量验证覆盖忙循环、休眠、兄弟核忙循环、角色互换及异常退出；休眠允许少量真实测量/唤醒开销，
不可用精确零要求掩盖真实执行，也不可给整个墙钟等待计费。阈值依据真实测量预检固定并记录，
不能在失败后抬高阈值挑选一次通过。

## 地址空间、用户态与共享业务

统一运行时采用高半区内核和低地址私有用户空间；具体链接基址由实现者在 x86 canonical 范围内
选定并记录。bootstrap 保留低物理装载入口，进入长模式后转到高半区。
用户页表仅共享 supervisor 内核映射，用户 RX/RO/RW 不映射任何可写可执行物理别名。
移除对 `VA == PA` 的全局假设，物理装载和虚拟链接地址分别校验。

实现每核可恢复的用户上下文：整数、标志、TLS、完整启用的 FP/SIMD 状态及私有返回栈。
内核编译/陷阱路径与保存范围匹配；未保存的扩展必须禁止。陷阱前后的内核与用户状态不得互相污染。
系统调用、定时器抢占、访问故障和恢复必须在每个 vCPU 上真实执行。
撤销或复用页框前等待所有相关 CPU 完成失效与引用释放；超时隔离资源，不能继续重用。

ELF loader 显式接收 ISA：ARM 183/入口对齐 4，x86 62/入口对齐 1；其余边界、W^X、段重叠和
映像大小约束保持。六个基础映像共享算法，只更换启动/调用 ABI；构建必须验证实际嵌入 ELF。
任务完成继续经过既有准入、信用预留、用户执行、真实 CPU 结算、退休与结果归属链。
Coordinator 的 DRAIN→QUIESCED→PUBLISH→APPLIED 使用真实 x86 停机、TLB、中断与引用证明。

## PC 设备和完整运行时

PCI 枚举与 BAR/capability 长度、范围及重叠校验位于 PC 层。VirtIO transport 增加现代 PCI
common/notify/ISR/device 配置适配，复用现有队列、block/net/rng 驱动及 DMA 生命周期。
设备内存和 DMA 页保持明确权限/可见性；错误长度、损坏链、超时或未知 capability 必须拒绝/隔离。
先验证真实块读写与持久恢复，再接入 RNG、网络、双节点受保护集群服务。
中断路由/屏蔽/EOI 和 in-flight 证明属于 PC 后端；轮询回退必须显式标记，不能伪造 IRQ 已执行。

“完整运行时完成”要求双节点 x86 客体运行既有核心服务、普通任务、持久文件、网络和学习组件，
没有用空实现返回成功来代替依赖服务。中间的任务或设备 profile 单独命名、单独报告能力。

## A03 路线及不变条件

继续使用 Untrained seed 起步，先采集真实 18 族、至少 144 条训练/72 条验证，完整实验组互斥。
客体原生训练、独立验证及 Shadow/Canary/Active 达标后，再执行 ordinary rise/fall。
保留现有 100 个真实请求/10 秒释放、撤回/排空、2 秒 quiet 和实际扩核/收核 APPLIED 门禁。
独立工具验证同一次运行的模型、ApplyID、quiet 回执与实际所有权链。

500 μs 发布（含解码）、2 ms 模型、1 MiB 学习工作区、10 秒观测、1 秒预热、5 秒收尾均不变。
不离线训练、不手调权重、不生成合成成功标签；历史 525332 ns 发布超时及未收缩证据保持有效。
平台移植完成不自动令 A03 PASS，训练成功也不自动证明真实普通场景完成。

## 验证与完成顺序

| 阶段 | 必须交付的实际结果 | 关键反例 |
| --- | --- | --- |
| 1 多核 | 四个真实 CPU 身份、私有描述符/栈、IPI、两轮停机/恢复 | 重复 ID、损坏 ACPI、漏 AP、旧 ACK、停机后旧工作继续 |
| 2 计量 | 每核独立执行 ns，闲置/兄弟核不被错误计费 | stock QEMU、单线程、缺/错能力、时钟失败、跨核戳 |
| 3 任务 | 私有用户地址空间、抢占/恢复、故障隔离和付费完成 | 错 ISA、越权访问、FP/TLS 泄漏、TLB 未完成回收 |
| 4 控制 | 原 Coordinator 和控制/学习/治理映像实际运行、真实所有权交接 | Pending 当完成、旧 ApplyID、预算退款、丢失引用/IRQ 证明 |
| 5 完整运行时 | 真实持久块、RNG、网络、双节点服务及普通工作 | 错设备、坏 DMA/队列、丢包/重启、密钥或结果串节点 |
| 6 A03 | 真实数据→客体训练→验证→Active→ordinary 1→2→1 | 数据泄漏、未训练模型冒充 Active、仅日志或 mask 变化 |

各阶段保留源码冻结、构建输入、编译器、QEMU 源码/二进制、profile、CPU/RAM、原始 QMP/串口、
退出状态和独立复核。为新 x86 证据建新版本；历史 ARM ABI/验证器不覆盖改写。
所有重编译、VM 和计时验证使用统一 native lease，避免并发争用制造不可解释的时间结果。
实现可拆为独立文件任务，集成、源码冻结和运行验证按依赖串行。

已有 `e5369c5` 回归是基线：942 项 Rust、18 项相关工具、PC dev/release TCG 与 CI 通过；
26 个既存宿主失败仍是已知历史状态。后续只把本轮实际执行结果记入新阶段。
