# CyxiaOS V0.20 原生单机强化开发记录（WIP，不可宣称发布验收）
 
版本：`0.20.0-dev`；代码基线：`CyxiaOS-V0.20` @ `0e832f6ed145d283bcbf08bd1ae680d04c1c1d4a`（源代码仍标记 `0.19.0-dev`，在本工作分支更新）。
 
## 设计原则

完整目标契约见 [V0.20 原生单机架构设计增补](../design/v0.20-native-local-system.md)，明确覆盖旧最小原型的动态控制核与 D16 双节点章节；设计不代表运行验收通过。
 
- V0.20 设计目标为固定 C={CPU0} 控制、B={CPU1–3} 业务（见 [V0.20 原生单机架构设计增补](../design/v0.20-native-local-system.md) §2）。2026-11-25 第二波整改已完成**代码层**拓扑切换：`control_plane/fixed.rs` 改为重新导出 `cpu0_v0199` 契约常量（单一权威来源，删除 CPU0 broker 概念），SEC-P/SEC-D/SEC-S 准入、默认 smp-selftest 夹具（`fixed_cpu0_fixture`，含负向与 fail-closed 断言）及源码守卫同步迁移；退休的动态 CoreSet 迁移夹具仅在 `legacy-coreset`/`ai-control-selftest` 显式特性下保留。**原生 QEMU TTBR/IRQ 读回、控制预算实测与完整回归仍 NOT_RUN**，不得以宿主/构建证据宣称原生拓扑验收。控制核健康失效时 fail closed，不把业务核提升为第二个控制核。
- 运营 AI 与安全 AI 各只进行观测、辅助分析和建议；独立的身份、邮箱及资源额度不能产生能力、批准、确定性裁决或执行。最终安全拒绝、资源账本、设备/文件确认必须由原生确定性机制完成。
- 所有本地内核基础机制和系统服务享有同等 AI 建议接入地位：观测→建议→独立校验→原生执行→关联反馈，热路径不等待模型。
- 六大安全方向：SEC-P 进程、SEC-F 文件、SEC-M 内存、SEC-N 网络、SEC-D 设备和 SEC-S 系统调用。原型单域主机测试不等于 ARM/x86 原生安全验收。
- 不保留集群发现、远程合同、分布式恢复或 D16 跨节点放置。必须保留独立本地 TCP/TLS、SMP、IPC、文件与设备的本机能力。
 
## 本工作分支已修改（尚未完成原生回归）
 
1. `control_plane::fixed::valid_layout` 明确排除 CPU0 作为业务核；新增错误布局的 Rust 负向断言。
2. AArch64 `domain_tasks::begin_control` 和 `verify_control_credit` 只允许 CPU0 拿取/核验控制预算凭证（门控为 `fixed::CONTROL_CPU`，第二波起重新导出 `cpu0_v0199` 契约常量 =0，CPU1–3 均为业务核）。历史口径：基线原为 CPU1|2 双入口，本分支先收紧为仅 CPU1（拒绝 CPU2 的旧控制预算入口），第二波 CPU0 拓扑切换将同一门控落到 CPU0。
3. AArch64 `prototype_runtime::step` 不再进入退休的 CPU2 第二控制工作器。
4. 更新开发版 VERSION 与分支说明；加入本分支针对源码和主机机制的并行 CI 入口、精确源码归档及散列。
5. 默认 workspace 测试入口不再编译历史 `cyxia-cluster-transport`，改为包含 `cyxia-net-transport` 与 `cyxia-local-echo`；旧集群模块 `peer-billing`/`cluster-transport` 已在根 `Cargo.toml` 的 `exclude`（不在 `members`），仅 `kernel/Cargo.toml` 为遗留诊断特性 `tcp-v13-selftest`/`unified-runtime` 保留可选依赖边，**仅完成默认入口隔离，未完成彻底去分布式**。
 
这些变更**只收紧固定核心入口**，还不能据此认定 ARM 70 ms / 100 ms 累计预算超限已被真实修复。必须复测所有必需控制任务、运营/安全 AI、学习/Shadow/Canary、恢复及 broker 计量，保存每窗口预留与实际 CPU 时间、超限和拒绝/降级证据。
