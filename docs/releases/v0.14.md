## A10 fault-arming repair

The previous backend counted WRITE/FLUSH requests immediately after NBD connection. A preboot management FLUSH during GDB configuration could consume mutation 1 and cut power before guest execution. The native verifier correctly rejected this; its post-resume condition remains intact.

The runner now performs PREPARE -> GDB injection -> exact readback -> one-shot quiescent ARM -> sole QMP cont. Arming is bound to the frozen input hash and serialized against complete request/reply batches. Pending replies, queued input, disconnected backends, preparation WRITE or repeated arming fail closed.

New v2 captures retain the absolute WRITE/FLUSH ordinal in `raw_mutation`. A distinct `mutation` is zero in PREPARE and starts at one after ARM; reads have zero mutation ordinals. All preparation requests, bytes, completions and ACKs remain archived. Thus `--cut 1` targets the first post-arm WRITE or FLUSH regardless of the number of preparation FLUSH requests. There is no fixed offset or blanket first-FLUSH exclusion.

The independent byte replayer reconstructs both counters, the empty ARM boundary and all durable bytes. The scope verifier binds ARM to the input and requires readback <= ARM <= the actual QMP resume request. Any armed request observed before resume is rejected. ARM occurs before first guest execution, not after mount or AI_ACTIVE, so recovery writes remain fault candidates.

Guest code, disk format, successful FLUSH semantics, before/after-ACK cuts, drop/reverse-half loss policies, CPU budgets and guest deadlines are unchanged. Default backend callers retain the legacy v1 absolute-numbering contract. Arbitrary debug reconnection or unmodeled management I/O during a native fault window remains prohibited; this change does not make those operations observationally harmless.

## Implementation and validation

Changed tools are `v13_fault_disk.py`, `check_v13_fault_disk.py`, `run_v13_a10.py` and `v13_a10_fault_scope.py`. The runner freezes `cut_scope=post-arm-v1`; the independent checker does not trust a producer PASS field.

```
python3 -B -m unittest discover -s tools -p 'test_a10_fault_arming.py' -v
python3 -B -m unittest discover -s tools -p 'test_*a10*.py' -v
```

The new suite has 12 host test methods. It includes 24 first-operation combinations: preparation FLUSH counts 0/1/3, before/after-ACK cuts, first WRITE/FLUSH, and reply reversal off/on. It also covers loss semantics, delayed completion, queued input, repeated arming, preparation writes, legacy numbering, tampered records and invalid resume boundaries. Synthetic lifecycle records are parser fixtures, not native receipts. The broader discovery overlaps the targeted suite; do not add their counts as unique tests.

At initial commit `3e7cb83a2cd6a955ef15473e3aadc871c330d620`, run `41266749699` passed all 12 arming methods but failed on a subsequent selector matching no files (`test_*fault_disk*.py`, exit 5). Packaging was correctly skipped. The follow-up removes that nonexistent selector, not failure handling. Compatibility remains covered by the actual-backend legacy test and the full tools lane. That failed run remains retained.

`Validate prototype branches` includes V0.14 and runs static/Rust/host/tools lanes. `V0.14 source snapshot` retains targeted host logs and packages the exact commit only after those checks pass. Consult the exact-commit run for outcomes; this document does not predeclare later CI results.

## Package and evidence boundaries

Artifact `CyxiaOS-V0.14-source-<commit>-<attempt>` contains `CyxiaOS-V0.14-source.zip`, `SHA256SUMS`, commit/tree identities and `validation-scope.json`. It is source only, not a bootable binary or signed release. CI retention is 30 days. Packaging does not imply native acceptance or completion of every separate engineering lane.

Do not resume an old A10 matrix with changed tool hashes or reinterpret its raw cut numbers as v2 scoped numbers. Preserve old failures with matching verifiers and generate a fresh probe/cut matrix. Full native A10 still requires interrupted recovery and post-ACK cross-endpoint/cache-eviction checks under the pinned patched QEMU.

The inherited A01 and VirtIO changes retain their original history and evidence. Earlier results do not automatically certify V0.14, and unresolved historical failures remain visible. The formal catalogue `docs/implementation/v13-requirements.json` is unchanged. Any mandatory FAIL or NOT_RUN prevents complete prototype acceptance under specification 1.3 section 14.5.
