# V0.20 SnapshotSlotStore 非空槽候选

候选采用 G1 D1.3 的槽址 `4132 + 15 × slot`。描述页之后按地址顺序存储 14 个 4 KiB 镜像页，
恰好容纳业务 inode 0–223 的 v1 字节，镜像范围止于系统 inode 段之前。
槽 0 和 SlotStore 共用首块，故其前 40 字节保留 D1.5 信封并绑定容器代际。
槽 1–7 的前 40 字节全零。所有非空槽从偏移 40 使用同一描述头。

候选描述头沿用 V18 的字段位置，采用版本 3 标记封装和校验范围变更。整数均为小端，表中偏移相对描述头。

| 偏移 | 字段 |
|---:|---|
| 0、4、6 | 魔数 `0x43595352`、版本 `3`、头长 `128` |
| 8、24、32 | 文件系统 UUID、快照 ID、槽号 |
| 40、48、56 | 槽代际、捕获 live-view epoch、所捕获已提交视图的 LSN |
| 64、68、72 | 业务 inode 数 `224`、镜像页数 `14`、镜像首块 |
| 80、112、120 | 14 页按序拼接的 SHA-256、捕获在线时长、描述 CRC32C |

未列字段置零。描述 CRC32C 覆盖绝对偏移 40 至块末尾，自身置零。槽 0 先完成描述 CRC，再按
D1.5 重算覆盖整块的信封 CRC32C。目录绑定包含整张描述页的 SHA-256 和独立捕获身份。
验证按绝对块地址读取，检查身份、两类 CRC、镜像 SHA-256 和 v1 inode 记录结构。目录树、位图和
业务数据归属需要真实介质和文件系统所有者的单独验证。

```sh
python3 -B tools/v020_snapshot_slot_vectors.py check
cargo test --locked -p cyxia-kernel-core --test snapshot_slot_candidate
```

Python 独立编解码固定 14 页样例与 14 组描述页向量。向量覆盖槽 0 和槽 7，以及镜像末页、物理位置、
UUID、容器与槽代际、捕获 LSN、保留字节和校验值的变更。Rust 对合法向量重编码逐字节比对，并验证
现有空槽视图拒绝它们。此字段设计和保留方式待 D7 正式审定。
